--- CONTENT_HTML ---
<h2 data-narration-id="n1">Why Data Structures Matter</h2>
<p data-narration-id="n2">When a program needs to store more than a few values, single variables become unmanageable. Imagine tracking the scores of 30 students with 30 separate variables &mdash; the code would be enormous and impossible to loop over. <dfn class="term" data-def="A way of organising and storing data in memory so that it can be accessed and manipulated efficiently.">Data structures</dfn> solve this by grouping related data together under one name. The three structures you need to understand are one-dimensional arrays, two-dimensional arrays and records. Each suits a different kind of problem.</p>

<h2 data-narration-id="n3">One-Dimensional Arrays</h2>
<p data-narration-id="n4">A <dfn class="term" data-def="A data structure that stores a fixed number of items of the same type in a single sequence, accessed by an index number.">one-dimensional array</dfn> is a list of items of the same data type, stored in a row. Every item is accessed using an index. In Python, indexing starts at 0, so the first element of an array called <code>scores</code> is <code>scores[0]</code>.</p>

<pre><code class="language-python"># Declaring a 1D array of five exam scores
scores = [72, 85, 61, 90, 78]

# Accessing the third element (index 2)
print(scores[2])   # outputs 61

# Changing an element
scores[0] = 75

# Looping over the whole array
for i in range(len(scores)):
    print(scores[i])
</code></pre>

<p data-narration-id="n5">Arrays store items of the <strong>same type</strong> &mdash; all integers, all strings, and so on. This is what makes them efficient: the computer knows the size of each element, so it can jump directly to any index in one step. You cannot mix data types in a single array.</p>

<div class="key-fact" data-narration-id="n6" data-revision-tip="Cover this and write a Python declaration for a 1D array of six temperatures. Then write the code to print the fourth element.">
  <div class="key-fact-label">Key Fact</div>
  <p>A 1D array stores a fixed set of same-type values in a single row. Access is by index number. In Python, the first index is 0, so an array of length 6 has valid indices 0 to 5.</p>
</div>

<h2 data-narration-id="n7">Two-Dimensional Arrays</h2>
<p data-narration-id="n8">A <dfn class="term" data-def="A data structure that stores data in a grid of rows and columns, accessed using two index numbers: one for the row and one for the column.">two-dimensional array</dfn> is a grid &mdash; think of a table or a spreadsheet. Each element needs two indices: a row index and a column index. A seating plan for a hall with 5 rows and 8 columns could be stored as a 2D array with 40 elements.</p>

<pre><code class="language-python"># 2D array: 3 students, 4 test scores each
results = [
    [72, 85, 61, 90],   # student 0
    [55, 70, 80, 65],   # student 1
    [88, 92, 76, 84]    # student 2
]

# Access student 1's third test score (row 1, column 2)
print(results[1][2])   # outputs 80

# Loop over all scores
for row in range(len(results)):
    for col in range(len(results[row])):
        print(results[row][col])
</code></pre>

<p data-narration-id="n9">The outer index selects the row; the inner index selects the column. A 2D array is ideal when data is naturally tabular &mdash; for example, a timetable or a grid-based game map. Like 1D arrays, all elements must be the same data type.</p>

<div class="key-fact" data-narration-id="n10" data-revision-tip="Write from memory: how do you access the element in row 2, column 3 of a 2D array called 'grid'? Write both the Python syntax and a sentence explaining what the two indices mean.">
  <div class="key-fact-label">Key Fact</div>
  <p>A 2D array uses two indices: <code>array[row][column]</code>. All elements must share the same data type. A 2D array of r rows and c columns holds r &times; c elements in total.</p>
</div>

<div class="collapsible">
  <button class="collapsible-toggle" aria-expanded="false">
    <span>Records: Grouping Mixed Data Types</span>
    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>
  </button>
  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n11">Arrays require all elements to be the same type. But a student record typically contains a name (string), an age (integer), a registration number (string) and a grade (character) &mdash; all different types. A <dfn class="term" data-def="A data structure that groups together a fixed set of named fields, which may be of different data types, to represent one entity.">record</dfn> stores different data types together under one structured name. Each piece of information within a record is called a field.</p>
    <p data-narration-id="n12">In Python, a record is commonly modelled as a dictionary or a class. For GCSE purposes, describe a record by listing its fields, their data types and their purposes:</p>
    <pre><code class="language-python"># A student record with four fields
student = {
    "name": "Aisha Patel",    # string
    "age": 16,                  # integer
    "reg_number": "24A017",    # string
    "grade": "B"                # character
}

print(student["name"])   # outputs Aisha Patel
</code></pre>
    <p data-narration-id="n13">Each field in a record has a name and a data type. Fields can be strings, integers, booleans, dates &mdash; anything. This flexibility is the key difference between a record and an array.</p>
  </div></div>
</div>

<div class="collapsible">
  <button class="collapsible-toggle" aria-expanded="false">
    <span>File Design: From Records to Files</span>
    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>
  </button>
  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n14">A file is a collection of related records stored on a secondary storage device (hard drive, SSD). A school database might store one record per student, with all records forming a file. When designing a file, you decide which fields each record needs and what data type and size each field should have.</p>
    <p data-narration-id="n15">A simple file design table for a student file might look like this:</p>
    <table data-narration-id="n16">
      <thead><tr><th>Field name</th><th>Data type</th><th>Example value</th><th>Purpose</th></tr></thead>
      <tbody>
        <tr><td>StudentID</td><td>String</td><td>24A017</td><td>Unique identifier for each student</td></tr>
        <tr><td>Surname</td><td>String</td><td>Patel</td><td>Student's family name</td></tr>
        <tr><td>Forename</td><td>String</td><td>Aisha</td><td>Student's given name</td></tr>
        <tr><td>YearGroup</td><td>Integer</td><td>11</td><td>Current school year</td></tr>
        <tr><td>FreeSchoolMeals</td><td>Boolean</td><td>True</td><td>Entitlement flag for funding</td></tr>
      </tbody>
    </table>
    <p data-narration-id="n17">Good file design avoids storing the same data twice (redundancy) and keeps each field focused on one piece of information. For example, storing &ldquo;full name&rdquo; as a single field makes it harder to sort by surname &mdash; separate Surname and Forename fields are better design.</p>
  </div></div>
</div>

<div class="collapsible">
  <button class="collapsible-toggle" aria-expanded="false">
    <span>Choosing the Right Data Structure</span>
    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>
  </button>
  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n18">The rule is straightforward: if all your data is the same type and you need to loop over it numerically, use an array. If your data has mixed types and represents one real-world entity, use a record. If you need to store many records persistently on disk, you need a file.</p>
    <p data-narration-id="n19">Examples to practise:</p>
    <ul>
      <li data-narration-id="n20">Monthly rainfall figures for 12 months &mdash; all the same type (real numbers), naturally sequential. Use a <strong>1D array</strong>.</li>
      <li data-narration-id="n21">Rainfall figures for 12 months across 5 cities &mdash; same type, two dimensions (city &times; month). Use a <strong>2D array</strong>.</li>
      <li data-narration-id="n22">Details about one patient (name, date of birth, blood group, NHS number) &mdash; mixed types, one entity. Use a <strong>record</strong>.</li>
      <li data-narration-id="n23">Details about thousands of patients stored permanently &mdash; many records. Use a <strong>file</strong> of patient records.</li>
    </ul>
  </div></div>
</div>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n25">Key Takeaways</h3>
<ul>
  <li data-narration-id="n26">A 1D array stores a fixed number of same-type items in a single sequence; a 2D array stores them in a grid accessed by two indices (row, then column).</li>
  <li data-narration-id="n27">A record groups fields of mixed data types to represent one real-world entity; a file is a collection of related records stored on secondary storage.</li>
  <li data-narration-id="n28">Choose arrays when data is all one type and looped numerically; choose records when fields have different types. Justify your choice by linking the structure to the data properties.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n24">In &ldquo;describe&rdquo; or &ldquo;justify&rdquo; questions about data structures, always state <em>why</em> the structure suits the problem &mdash; not just which one to use. For a 1D array: &ldquo;because all 12 values are the same data type (integer) and can be accessed by a loop using a single index.&rdquo; For a record: &ldquo;because the fields have different data types (string for name, integer for age) representing one entity.&rdquo; One-word answers score zero; a reason earns the extra mark. When designing file fields, always include the data type alongside the field name.</p>
