--- CONTENT_HTML ---
<h2 data-narration-id="n1">Logic in Computing</h2>
<p data-narration-id="n2">Every decision a computer makes &mdash; whether to grant access, whether a value is in range, whether to send a notification &mdash; is ultimately a logical operation. The three fundamental <dfn class="term" data-def="Operators that combine or modify Boolean (True/False) conditions: AND, OR and NOT.">logical operators</dfn> are AND, OR and NOT. A <dfn class="term" data-def="A table that shows the output of a logical expression for every possible combination of True/False inputs.">truth table</dfn> is the tool used to show exactly what output a logical expression produces for every possible combination of inputs. Your specification requires you to construct truth tables for expressions using AND, OR and NOT with up to three inputs.</p>

<div class="key-fact" data-narration-id="n3" data-revision-tip="Cover this and write out the truth table for AND, OR and NOT from memory. Check all rows.">
  <div class="key-fact-label">Key Fact</div>
  <p>There are only three operators to know: <strong>AND</strong> returns True only when <em>both</em> inputs are True. <strong>OR</strong> returns True when <em>at least one</em> input is True. <strong>NOT</strong> flips a single input &mdash; True becomes False and False becomes True.</p>
</div>

<h2 data-narration-id="n4">AND &mdash; Both Must Be True</h2>
<p data-narration-id="n5">The <dfn class="term" data-def="A logical operator that returns True only when every input connected to it is True; returns False in all other cases.">AND operator</dfn> requires every input to be True before the output is True. In real systems: a bank transfer is authorised only if the user is authenticated AND the account has sufficient funds. Both conditions must hold.</p>
<p data-narration-id="n6">Truth table for AND with two inputs A and B:</p>
<p data-narration-id="n7">A = False, B = False &rarr; Output = False<br/>
A = False, B = True &rarr; Output = False<br/>
A = True, B = False &rarr; Output = False<br/>
A = True, B = True &rarr; Output = <strong>True</strong><br/>
Only the last row gives True. &ldquo;All or nothing.&rdquo;</p>

<h2 data-narration-id="n8">OR &mdash; At Least One Must Be True</h2>
<p data-narration-id="n9">The <dfn class="term" data-def="A logical operator that returns True when at least one of its inputs is True; returns False only when all inputs are False.">OR operator</dfn> returns True when at least one input is True. In real systems: a security alarm triggers if a door sensor is activated OR a motion sensor is activated. Either one is enough.</p>
<p data-narration-id="n10">Truth table for OR with two inputs A and B:</p>
<p data-narration-id="n11">A = False, B = False &rarr; Output = False<br/>
A = False, B = True &rarr; Output = <strong>True</strong><br/>
A = True, B = False &rarr; Output = <strong>True</strong><br/>
A = True, B = True &rarr; Output = <strong>True</strong><br/>
Only the first row (both False) gives False. &ldquo;Anything works.&rdquo;</p>

<h2 data-narration-id="n12">NOT &mdash; Flip the Input</h2>
<p data-narration-id="n13">The <dfn class="term" data-def="A logical operator that takes a single input and reverses its truth value: True becomes False and False becomes True.">NOT operator</dfn> takes a single input and reverses it. In real systems: a smart light turns on if NOT(daylight) &mdash; meaning it is on only when daylight is False (i.e. it is dark).</p>
<p data-narration-id="n14">Truth table for NOT with input A:</p>
<p data-narration-id="n15">A = False &rarr; NOT A = <strong>True</strong><br/>
A = True &rarr; NOT A = <strong>False</strong></p>

<div class="key-fact" data-narration-id="n16" data-revision-tip="Test yourself: for two inputs A and B, how many rows does a truth table need? For three inputs A, B and C, how many rows?">
  <div class="key-fact-label">Key Fact</div>
  <p>The number of rows in a truth table is 2 raised to the power of the number of inputs. Two inputs: 2<sup>2</sup> = 4 rows. Three inputs: 2<sup>3</sup> = 8 rows. Always work through the rows systematically &mdash; a consistent pattern (e.g. alternating True/False for the last column, then pairs for the second, then groups of four for the first) ensures you never miss a combination.</p>
</div>

    <p data-narration-id="n18"><strong>Step 1:</strong> List all combinations of A and B (4 rows for 2 inputs). Use a systematic pattern &mdash; last column alternates T/F; first column alternates in pairs:<br/>

Row 2: A=False, B=True<br/>
Row 3: A=True, B=False<br/>

Row 1: NOT B = True<br/>
Row 2: NOT B = False<br/>
Row 3: NOT B = True<br/>
Row 4: NOT B = False</p>
    <p data-narration-id="n20"><strong>Step 3:</strong> Apply AND to A and NOT B:<br/>
Row 1: False AND True = False<br/>
Row 2: False AND False = False<br/>
Row 3: True AND True = <strong>True</strong><br/>
Row 4: True AND False = False</p>
    <p data-narration-id="n21">The expression is True only in row 3 &mdash; when A is True and B is False. Reading this as a real decision: &ldquo;the feature is active only if option A is enabled AND option B is disabled.&rdquo;</p>
  </div></div>
</div>

<h2 data-narration-id="n22">Three-Input Truth Tables</h2>
<p data-narration-id="n23">When an expression has three inputs (A, B and C), there are 2<sup>3</sup> = 8 possible combinations. The approach is exactly the same: list all 8 rows systematically, then evaluate any intermediate expressions column by column before arriving at the final output.</p>
<p data-narration-id="n24">Example expression: (A AND B) OR (NOT C). To evaluate this, you need three columns: one for A AND B, one for NOT C, and one for the whole expression using OR.</p>

  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n25">All 8 rows with systematic input listing (C alternates T/F every row; B alternates every two rows; A alternates every four rows):</p>
    <p data-narration-id="n26"><strong>Row 1:</strong> A=F, B=F, C=F &rarr; A AND B = F; NOT C = T; F OR T = <strong>True</strong></p>
    <p data-narration-id="n27"><strong>Row 2:</strong> A=F, B=F, C=T &rarr; A AND B = F; NOT C = F; F OR F = <strong>False</strong></p>
    <p data-narration-id="n28"><strong>Row 3:</strong> A=F, B=T, C=F &rarr; A AND B = F; NOT C = T; F OR T = <strong>True</strong></p>
    <p data-narration-id="n29"><strong>Row 4:</strong> A=F, B=T, C=T &rarr; A AND B = F; NOT C = F; F OR F = <strong>False</strong></p>
    <p data-narration-id="n30"><strong>Row 5:</strong> A=T, B=F, C=F &rarr; A AND B = F; NOT C = T; F OR T = <strong>True</strong></p>
    <p data-narration-id="n31"><strong>Row 6:</strong> A=T, B=F, C=T &rarr; A AND B = F; NOT C = F; F OR F = <strong>False</strong></p>
    <p data-narration-id="n32"><strong>Row 7:</strong> A=T, B=T, C=F &rarr; A AND B = T; NOT C = T; T OR T = <strong>True</strong></p>
    <p data-narration-id="n33"><strong>Row 8:</strong> A=T, B=T, C=T &rarr; A AND B = T; NOT C = F; T OR F = <strong>True</strong></p>
    <p data-narration-id="n34">The output is True in five of the eight rows: rows 1, 3, 5, 7, and 8. Notice that whenever C is False, NOT C is True, making the OR output True regardless of A and B. The output is only False when A AND B is False <em>and</em> C is True.</p>
  </div></div>
</div>

<h2 data-narration-id="n35">Using Logic to Solve Real Problems</h2>
<p data-narration-id="n36">Truth tables are not just exam exercises &mdash; they describe the <dfn class="term" data-def="A data type or value that can be only True or False, used as the input and output of logical operations.">Boolean</dfn> logic that controls real systems. An e-commerce checkout might use: (item in stock AND payment verified) OR (pre-order enabled). A content filter might use: NOT(verified age) AND content is restricted. Constructing the truth table for any such expression tells you exactly when the output will be True, allowing a programmer to verify the logic before writing a single line of code.</p>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n38">Key Takeaways</h3>
<ul>
  <li data-narration-id="n39">AND returns True only when all inputs are True. OR returns True when at least one input is True. NOT reverses a single input. These three operators are the building blocks of all logical decisions in computing.</li>
  <li data-narration-id="n40">A truth table has 2 raised to the power of n rows, where n is the number of inputs. Two inputs give 4 rows; three inputs give 8 rows.</li>
  <li data-narration-id="n41">For compound expressions, add a column for each sub-expression and evaluate them in order before combining into the final output column.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n37">For a <strong>Complete a Truth Table</strong> question, always work column by column rather than row by row &mdash; evaluate all intermediate expressions in their own columns first. Use a systematic input pattern: the last column alternates T/F every row, the second-to-last alternates every two rows, and so on. Never skip the intermediate columns for compound expressions &mdash; examiners award marks for intermediate working as well as the final output. Remember: AND returns True only when <em>all</em> inputs are True; OR returns True when <em>any</em> input is True; NOT simply flips the value.</p>
