--- CONTENT_HTML ---
<h2 data-narration-id="n1">Trace Tables &mdash; Following an Algorithm Step by Step</h2>
<p data-narration-id="n2">A <dfn class="term" data-def="A table used to record the values of variables at each step of an algorithm's execution, with each column representing one variable or the output and each row showing the state after one step.">trace table</dfn> lets you follow an algorithm manually, recording the value of every variable at each step. Each column in the table represents a variable (or the output); each row represents the state of the algorithm after one step has executed. Trace tables are the standard method for finding logic errors and for checking that an algorithm produces the correct result for a given set of input data.</p>

<div class="key-fact" data-narration-id="n3" data-revision-tip="Cover this and list the two most common errors students make when completing a trace table in an exam.">
  <div class="key-fact-label">Key Fact</div>
  <p>The two most common trace-table errors in exams are: (1)&nbsp;adding extra rows for iterations that did not actually happen, and (2)&nbsp;forgetting to update a counter variable on every iteration. One row per state change &mdash; no more, no less.</p>
</div>

    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>

  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n4">Consider this algorithm in plain-English pseudocode:</p>
    <p data-narration-id="n5">1. Set total to 0.<br/>
    2. Set counter to 1.<br/>
    3. While counter is less than or equal to 4:<br/>
    &nbsp;&nbsp;&nbsp;a. Add counter to total.<br/>
    &nbsp;&nbsp;&nbsp;b. Add 1 to counter.<br/>
    4. Display total.</p>
    <p data-narration-id="n6">Trace table (columns: counter, total, output):</p>
    <p data-narration-id="n7"><strong>Before loop:</strong> counter = 1, total = 0.</p>
    <p data-narration-id="n8"><strong>Iteration 1:</strong> condition 1 &le; 4 is True. total = 0 + 1 = 1. counter = 2.</p>
    <p data-narration-id="n9"><strong>Iteration 2:</strong> condition 2 &le; 4 is True. total = 1 + 2 = 3. counter = 3.</p>
    <p data-narration-id="n10"><strong>Iteration 3:</strong> condition 3 &le; 4 is True. total = 3 + 3 = 6. counter = 4.</p>
    <p data-narration-id="n11"><strong>Iteration 4:</strong> condition 4 &le; 4 is True. total = 6 + 4 = 10. counter = 5.</p>
    <p data-narration-id="n12"><strong>Check condition:</strong> 5 &le; 4 is False. Loop ends. Output: 10.</p>
    <p data-narration-id="n13">The algorithm sums the integers from 1 to 4, producing 10. Its purpose: sum the integers from 1 to n (where n = 4).</p>
  </div></div>
</div>

<h2 data-narration-id="n14">Three Types of Error</h2>
<p data-narration-id="n15">Three categories of error can occur in programs. Understanding exactly what each type means is important &mdash; examiners report that many students give vague definitions that could apply to more than one type.</p>
<p data-narration-id="n16">A <dfn class="term" data-def="An error that occurs when the rules of a programming language have been broken, causing the program to be rejected before it can run.">syntax error</dfn> occurs when the rules of the programming language have been broken. The program cannot run at all &mdash; the language processor detects the error before execution begins. A misspelled keyword or a missing bracket are syntax errors. The key definition, word for word: <strong>the rules of the programming language have been broken</strong>. Avoid saying &ldquo;a spelling mistake&rdquo; in isolation &mdash; this is too vague and could describe a logic error too.</p>
<p data-narration-id="n17">A <dfn class="term" data-def="An error where the program runs without crashing but produces incorrect results because the algorithm's logic is wrong.">logic error</dfn> occurs when the program runs without crashing but produces incorrect results. The syntax is valid; the code executes; but the outcome is wrong. A common example: using a greater-than sign (&gt;) where a greater-than-or-equal-to sign (&ge;) was intended, causing the program to exclude a boundary value.</p>
<p data-narration-id="n18">A <dfn class="term" data-def="An error that occurs while a program is running, caused by an operation the processor cannot carry out, such as dividing by zero or accessing memory that does not exist.">runtime error</dfn> occurs while the program is executing. The syntax is valid and the program starts running, but it encounters an operation it cannot complete &mdash; such as dividing a number by zero, or attempting to access an index position that does not exist in an array. The program crashes or is forced to stop.</p>

    <p data-narration-id="n20"><strong>Logic error example:</strong> A grading program is intended to give a Merit to students scoring 70 or above. The developer writes the condition as &ldquo;if the score is greater than 70&rdquo; instead of &ldquo;greater than or equal to 70&rdquo;. The program runs without error, but a student with exactly 70 receives Pass instead of Merit &mdash; the result is wrong.</p>
    <p data-narration-id="n21"><strong>Runtime error example:</strong> A program divides a student&rsquo;s total marks by the number of assessments taken. If the student has taken zero assessments (perhaps they are a new enrolment), the program attempts to divide by zero &mdash; this is an operation the processor cannot complete, and the program crashes.</p>

<h2 data-narration-id="n22">Fitness for Purpose and Algorithm Efficiency</h2>
<p data-narration-id="n23">An algorithm is <dfn class="term" data-def="Describes an algorithm that correctly solves the problem it was designed for, producing the right output for all valid inputs including boundary cases.">fit for purpose</dfn> if it correctly solves the intended problem for all valid inputs, including boundary values and edge cases. You can check fitness for purpose by using logical reasoning and by running the algorithm with carefully chosen test data.</p>
<p data-narration-id="n24">Even if an algorithm is correct, it may not be <em>efficient</em>. Your specification identifies three measures of <dfn class="term" data-def="A measure of how well an algorithm uses computational resources, assessed by the number of comparisons, number of loop passes, and amount of memory used.">efficiency</dfn>: the number of comparisons made, the number of passes through a loop, and the use of memory.</p>

<div class="key-fact" data-narration-id="n25" data-revision-tip="Cover this and write down the three efficiency measures from the specification. For each, give one example of an algorithm where that measure matters.">
  <div class="key-fact-label">Key Fact</div>
  <p>Efficiency is measured in three ways: (1)&nbsp;<strong>number of comparisons</strong> &mdash; how many times the algorithm checks a condition against a value (important in searching: binary search needs far fewer comparisons than linear search for large datasets); (2)&nbsp;<strong>number of passes through a loop</strong> &mdash; how many times a loop body executes (important in sorting: bubble sort may need many passes); (3)&nbsp;<strong>use of memory</strong> &mdash; how much storage the algorithm needs (important in sorting: merge sort needs extra memory for sub-lists; bubble sort does not).</p>
</div>

<div class="collapsible">
  <button class="collapsible-toggle" aria-expanded="false">

    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>
  </button>
  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n26">To evaluate an algorithm, ask three questions:</p>
    <p data-narration-id="n27"><strong>1. Is it correct?</strong> Trace through the algorithm with a normal input, a boundary input (e.g. the minimum or maximum valid value), and an edge case (e.g. an empty list). Does the output match what was expected in every case?</p>
    <p data-narration-id="n28"><strong>2. Is it efficient?</strong> Count the number of comparisons and loop passes for a given input size. If the dataset doubles in size, does the algorithm take twice as long, or much longer? Bubble sort on a list of 100 items needs many more passes than on a list of 10 &mdash; the number of passes grows with the size of the problem.</p>
    <p data-narration-id="n29"><strong>3. Does it use memory wisely?</strong> Does the algorithm create large temporary structures (like the sub-lists in merge sort)? On a device with limited RAM &mdash; such as an embedded system in a medical device &mdash; high memory use could cause problems even if the algorithm is correct.</p>
  </div></div>
</div>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n31">Key Takeaways</h3>
<ul>
  <li data-narration-id="n32">A trace table records the value of every variable at each step; one row per state change, no extras. It is the standard method for checking an algorithm's correctness and finding logic errors.</li>
  <li data-narration-id="n33">Three error types: syntax (rules broken, program won't run), logic (program runs but gives wrong results), runtime (program crashes during execution, e.g. division by zero).</li>
  <li data-narration-id="n34">Algorithm efficiency is measured by number of comparisons, number of loop passes, and use of memory. An algorithm must also be fit for purpose &mdash; correct for all valid inputs including boundary and edge cases.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n30">The most commonly lost marks on trace table questions are: adding too many rows (trace only steps that actually execute), and not updating every variable on each row. For error-type questions, the precise definition of a syntax error is &ldquo;the rules of the programming language have been broken&rdquo; &mdash; avoid writing &ldquo;a spelling mistake&rdquo; alone, as this is ambiguous. For a 4-mark <strong>Explain</strong> question on algorithm efficiency, state the measure (number of comparisons / passes / memory use) and then explain <em>why</em> that matters in the given scenario &mdash; a statement of fact alone earns only half the marks.</p>
