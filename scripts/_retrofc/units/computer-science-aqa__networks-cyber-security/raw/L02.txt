Authentication, encryption, firewalls, MAC filtering and how the four-layer TCP/IP model organises traffic.

--- CONTENT_HTML ---
<h2 data-narration-id="n1">Why Network Security Matters</h2>
<p data-narration-id="n2">Every device connected to a network is a potential target. A school network holds thousands of student records; a hospital network carries patient data; a retail network processes payment details. <dfn class="term" data-def="The processes, practices and technologies designed to protect network infrastructure, devices and data from unauthorised access, damage or attack.">Network security</dfn> refers to the combination of measures used to protect these systems. No single measure is perfect, so effective security uses multiple layers working together.</p>

<div class="key-fact" data-narration-id="n3" data-revision-tip="Cover this and recall: name the four methods of network security from the specification and write one sentence about each.">
  <div class="key-fact-label">Key Fact</div>
  <p>The four network security methods you must know are: <strong>authentication</strong> (verifying who a user is), <strong>encryption</strong> (scrambling data so it cannot be read if intercepted), <strong>firewalls</strong> (monitoring and filtering network traffic), and <strong>MAC address filtering</strong> (allowing or blocking devices based on their hardware address).</p>
</div>

<h2 data-narration-id="n4">Authentication</h2>
<p data-narration-id="n5"><dfn class="term" data-def="The process of verifying the identity of a user or device before granting access to a network or system.">Authentication</dfn> is the first line of defence. Before a user can access a network, the system must confirm who they are. The simplest form is a username and password: the username identifies the user, and the password proves it is really them. Stronger authentication uses multiple factors &mdash; for example, a password combined with a one-time code sent to a mobile phone (two-factor authentication). Authentication ensures that only authorised users can access resources, even if an attacker knows the network exists.</p>

<h2 data-narration-id="n6">Encryption</h2>
<p data-narration-id="n7"><dfn class="term" data-def="The process of converting data into a coded form (ciphertext) using a key, so it cannot be read by anyone who does not have the decryption key.">Encryption</dfn> protects data in transit and in storage. When data is encrypted, it is transformed into ciphertext &mdash; an unreadable scramble of characters. Only someone with the correct decryption key can restore it to its original form. On networks, encryption is used by HTTPS (which encrypts web traffic between a browser and a server) and by secure email systems. Even if an attacker intercepts encrypted data travelling across a network, they cannot read it without the key.</p>

<h2 data-narration-id="n8">Firewalls</h2>
<p data-narration-id="n9">A <dfn class="term" data-def="A network security device that monitors incoming and outgoing network traffic and decides whether to allow or block specific traffic based on a defined set of security rules.">firewall</dfn> acts as a gatekeeper between a trusted internal network and an untrusted external network such as the internet. It examines each packet of data and decides whether to allow it through or block it, based on predefined rules. For example, a school might configure its firewall to block traffic to certain categories of website, or to block all incoming connections on ports not needed for school systems. Firewalls can be hardware devices, software running on a computer, or a combination of both.</p>

<h2 data-narration-id="n10">MAC Address Filtering</h2>
<p data-narration-id="n11">Every network interface card (NIC) has a unique <dfn class="term" data-def="A unique hardware address permanently assigned to a network interface card by the manufacturer. It is used to identify devices at the network hardware level.">MAC address</dfn> (Media Access Control address) assigned by its manufacturer. MAC address filtering uses this address to control which devices can connect to a network. A network administrator creates a list of approved MAC addresses; only devices on the list can access the network. This is useful for restricting access to a wireless network in a school, preventing unauthorised devices from connecting even if they know the Wi-Fi password. A limitation is that MAC addresses can be changed in software (called MAC spoofing), so it should not be relied upon as the sole security measure.</p>

MAC address filtering prevents unauthorised devices from connecting. A firewall blocks suspicious traffic that does reach the network. Encryption protects data even if it is intercepted in transit. Each layer compensates for the weaknesses of the others. For example, a firewall cannot protect against an attacker who already has valid credentials &mdash; but authentication can. Together, they provide a much stronger defence than any single measure alone.</p>

<h2 data-narration-id="n13">The Four-Layer TCP/IP Model</h2>
<p data-narration-id="n14">When data travels across a network, the process is organised into four distinct layers. Each layer handles a specific job, and data passes through all four layers on its way from sender to receiver. This is the <dfn class="term" data-def="A four-layer model that describes how data is transmitted across a network. The layers are: Application, Transport, Internet, and Link. Each layer has a specific role in preparing data for transmission.">TCP/IP model</dfn>, named after its two key protocols. Using layers means each component can be developed and updated independently: a new application protocol can be added without changing how packets are routed.</p>

<div class="key-fact" data-narration-id="n15" data-revision-tip="Write the four layers from top to bottom, then name one protocol or piece of hardware that belongs at each layer.">
  <div class="key-fact-label">Key Fact</div>
  <p>The four layers of the TCP/IP model, from top to bottom: <strong>Application</strong> (where network applications operate &mdash; HTTP, HTTPS, SMTP, IMAP), <strong>Transport</strong> (sets up communication and manages packets &mdash; TCP), <strong>Internet</strong> (addressing and routing packets &mdash; IP), <strong>Link</strong> (network hardware and drivers &mdash; NIC, OS device drivers).</p>
</div>

<div class="collapsible">
  <button class="collapsible-toggle" aria-expanded="false">
    <span>Each Layer Explained</span>
    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>
  </button>
  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n16"><strong>Application layer</strong> &mdash; this is where network applications operate. Web browsers, email clients, and file transfer tools all sit at this layer. The protocols at this layer &mdash; HTTP, HTTPS, SMTP, and IMAP &mdash; define how those applications format and exchange data.</p>
    <p data-narration-id="n17"><strong>Transport layer</strong> &mdash; sets up the communication session between two hosts and agrees settings such as the size of data packets. TCP operates at this layer, providing reliable, ordered delivery by breaking data into packets, numbering them, and checking they all arrive correctly. If a packet is lost, TCP requests it again.</p>
    <p data-narration-id="n18"><strong>Internet layer</strong> &mdash; handles addressing and routing. IP operates at this layer: it assigns a source and destination IP address to each packet and determines the best path through the network of routers to reach the destination.</p>
    <p data-narration-id="n19"><strong>Link layer</strong> &mdash; the lowest layer, responsible for the physical transmission of data across a single link. The network interface card (NIC) sits here, along with the operating system&rsquo;s device drivers that communicate with it. This layer handles the actual electrical or optical signals on the cable or wireless channel.</p>
    <p data-narration-id="n20">When data is sent, it passes <em>down</em> through the layers on the sender&rsquo;s device (Application &rarr; Transport &rarr; Internet &rarr; Link), crosses the network physically, and then passes <em>up</em> through the layers on the receiver&rsquo;s device (Link &rarr; Internet &rarr; Transport &rarr; Application) to be reassembled and delivered to the application.</p>
  </div></div>
</div>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n22">Key Takeaways</h3>
<ul>
  <li data-narration-id="n23">The four network security methods are: authentication (verifying identity), encryption (protecting data in transit), firewalls (filtering traffic by rules), and MAC address filtering (allowing only approved hardware addresses).</li>
  <li data-narration-id="n24">The TCP/IP model has four layers: Application (where protocols like HTTP, HTTPS, SMTP, IMAP operate), Transport (TCP &mdash; reliable packet delivery), Internet (IP &mdash; addressing and routing), and Link (NIC and OS drivers).</li>
  <li data-narration-id="n25">Using multiple security layers is more effective than relying on any single measure, as each compensates for the limitations of the others.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n21">For TCP/IP model questions, learn which protocols sit at which layer and the function of each layer. The most common mistakes are: placing IP at the Transport layer (it belongs at the Internet layer), or placing TCP at the Application layer (it belongs at Transport). Remember: HTTP, HTTPS, SMTP and IMAP are all at the Application layer; TCP is at Transport; IP is at Internet; and the NIC and OS drivers are at the Link layer. When explaining network security measures, link each method to what it protects against &mdash; do not just define the term.</p>
