How data is collected and how validation and verification techniques ensure accurate data entry.

--- CONTENT_HTML ---
<h2 data-narration-id="n1">How Data Is Captured</h2>
<p data-narration-id="n2"><dfn class="term" data-def="The methods and devices used to collect raw data and enter it into a computer system for processing.">Data capture</dfn> refers to the methods and tools used to collect data and get it into a computer system. The method chosen has a big impact on accuracy, speed and cost. Manual methods include keyboard entry (typing data into a form or spreadsheet) and handwriting on paper forms that are later typed up. These methods are flexible but slow and prone to human error. Automated methods capture data without (or with minimal) human typing. A barcode scanner reads product codes at a supermarket checkout. A magnetic stripe or chip on a payment card is read by a card reader. Optical Character Recognition (OCR) software converts printed or handwritten text in a scanned image into editable digital text. Optical Mark Recognition (OMR) detects pencil marks in fixed positions on a form — used in multiple-choice exam answer sheets and lottery tickets. Sensors capture environmental data automatically: a temperature sensor on a weather station records readings every minute without any human involvement. Online forms with drop-down menus and checkboxes guide users toward valid entries, reducing errors compared to completely free-text entry.</p>

<p data-narration-id="n3">No data capture method is perfect. Even automated systems can misread a damaged barcode or a smudged form. The data that enters a system must be checked for errors before it is stored or processed, otherwise the resulting information will be unreliable. Two distinct processes are used for this: <strong>validation</strong> and <strong>verification</strong>.</p>

<h2 data-narration-id="n4">Validation</h2>
<p data-narration-id="n5"><dfn class="term" data-def="An automated check performed by a computer to ensure that data entered into a field is reasonable, sensible and in the correct format — though it cannot confirm the data is factually correct.">Validation</dfn> is an automated check carried out by the computer to test whether data is reasonable and in the correct format. It is important to understand what validation <em>cannot</em> do: it cannot confirm that the data is factually true. For example, if a date-of-birth field expects a date in the past and a user types 01/01/2010, validation will accept it as a plausible date — even if the real date of birth is 01/01/2009. Validation simply checks that the data <em>could</em> be correct.</p>

<p data-narration-id="n6">There are several types of validation check:</p>

<p data-narration-id="n7">A <strong>range check</strong> confirms that a numeric value falls within acceptable limits. For instance, a student's exam mark out of 100 must be between 0 and 100 — the system would reject -5 or 150. A <strong>type check</strong> (also called a data type check) confirms that the data entered matches the expected data type for that field. A name field expects text; if a user enters numbers, the type check rejects the entry. A <strong>presence check</strong> ensures that a required field has not been left blank — useful for mandatory fields such as a customer's surname or email address. A <strong>format check</strong> (also called a picture check) verifies that the data matches a specific pattern. A UK postcode must follow a pattern such as SW1A 1AA; a date must follow DD/MM/YYYY. A <strong>length check</strong> confirms that the entry is within an acceptable number of characters — a mobile phone number in the UK should be 11 digits, so the system would reject an entry of 8 or 15 digits. Finally, a <strong>check digit</strong> is an extra digit added to a code (such as an ISBN book number or barcode) that is calculated mathematically from the other digits. When the code is entered, the system recalculates the check digit and compares it to the one entered — a mismatch reveals a keying error.</p>

<div class="key-fact" data-narration-id="n8" data-revision-tip="Learn the six validation check types: range, type, presence, format, length, check digit. For each, be ready to give a real-world example of where it would be used and what kind of error it catches.">
  <div class="key-fact-label">Key Fact</div>
  <p>The six validation checks are: range check (value within limits), type check (correct data type), presence check (field not empty), format check (correct pattern), length check (correct number of characters), check digit (mathematical digit to spot keying errors).</p>
</div>

<h2 data-narration-id="n9">Verification</h2>
<p data-narration-id="n10"><dfn class="term" data-def="A process of checking that data has been transferred from one place to another accurately and without change — confirming the copy matches the source.">Verification</dfn> checks that data has been copied or transferred correctly from one place to another. Unlike validation, verification does not check whether the data is reasonable — it checks whether it has been faithfully reproduced. There are two main verification methods. <dfn class="term" data-def="A verification technique in which the same data is entered into a system twice; the computer compares both entries and flags any difference.">Double entry</dfn> (also called double keying) requires a user to type the data twice — the computer compares the two entries and flags any difference. This is commonly used when setting a new password: you type it once, then again to confirm. If the two entries do not match, you are asked to try again. <strong>Proof reading</strong> is a human review of data before it is confirmed — a member of staff reads through entered data and compares it against the original source document to spot any errors. This is less automated but can catch subtle mistakes that a computer might miss.</p>

<div class="key-fact" data-narration-id="n11" data-revision-tip="The key distinction: validation is done BY THE COMPUTER and checks whether data is sensible. Verification is a check — human or automated — that data has been COPIED CORRECTLY from a source. Neither alone guarantees data is factually true.">
  <div class="key-fact-label">Key Fact</div>
  <p>Validation = automated computer check that data is reasonable and in the right format. Verification = check that data has been accurately transferred or copied. Double entry and proof reading are the two main verification techniques.</p>
</div>

<h2 data-narration-id="n12">Sources of Error</h2>
<p data-narration-id="n13">Errors can enter a system at multiple points. <strong>Transcription errors</strong> occur when data is copied from one place to another — a typist accidentally hits "8" instead of "9", or two adjacent characters are swapped (a transposition error). <strong>Transmission errors</strong> happen during the transfer of data over a network — interference or signal degradation can corrupt data in transit. <strong>Original source errors</strong> occur when the original data is simply wrong from the start — a customer gives an incorrect telephone number, or a sensor is miscalibrated. <strong>Data loss</strong> can occur during processing if a system crashes before data is saved. <strong>Deliberate falsification</strong> is where a person intentionally enters false information — for example, giving a false age on a website form. No single checking technique can prevent all of these errors, which is why systems combine multiple approaches.</p>

Verification is appropriate when data has been copied from a source document and you need to confirm the copy is accurate — for example, a data entry clerk typing patient records from paper forms. The two methods are complementary: a data entry system might validate each field as the clerk types, AND ask the clerk to proof read the final record against the paper form before clicking Submit. Together they dramatically reduce the rate of errors that reach the database.</p>

    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>
  </button>
  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n15">A check digit is the final digit of a product barcode or ISBN, calculated mathematically from all the preceding digits using a set algorithm. For example, in an ISBN-13, each of the first 12 digits is multiplied alternately by 1 and 3, the results are summed, and the check digit is the number needed to make the total divisible by 10. When a barcode is scanned at a till, the system repeats this calculation on the first 12 digits. If the result matches the scanned check digit, the data is accepted. If there is a mismatch — caused, for example, by a scanning error or a damaged barcode — the system alerts the operator. Check digits are particularly effective at catching transposition errors (where two digits are accidentally swapped) because swapping changes the calculated total.</p>
  </div></div>

<h3 data-narration-id="n17">Key Takeaways</h3>
<ul>
  <li data-narration-id="n18">Data capture methods include keyboard entry, barcode scanners, OCR, OMR, sensors and online forms — each with different accuracy and speed trade-offs.</li>
  <li data-narration-id="n19">Validation is an automated computer check that data is reasonable and in the correct format; it cannot confirm data is factually true.</li>
  <li data-narration-id="n20">The six types of validation check are: range, type, presence, format, length and check digit.</li>
  <li data-narration-id="n21">Verification confirms that data has been copied or transferred correctly; the two main methods are double entry and proof reading.</li>
  <li data-narration-id="n22">Sources of error include transcription errors, transmission errors, original source errors, data loss and deliberate falsification — no single technique prevents all of them.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n16">A common exam mistake is to confuse validation and verification. Remember: validation is done by the computer and checks if the data is <em>reasonable</em> — it cannot tell you if the data is actually true. Verification checks that the data has been <em>copied correctly</em>. If the question gives you a scenario, identify which type of error is at risk: if data is being transferred or re-keyed, think verification; if the question asks whether entered values make sense, think validation. When naming a validation check, always name the specific type (range, type, presence, format, length or check digit) rather than just saying "the computer checks the data" — the specific type earns the mark.</p>
