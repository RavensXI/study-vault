--- CONTENT_HTML ---
<h2 data-narration-id="n1">How Computers Store Text</h2>
<p data-narration-id="n2">A computer stores everything as binary &mdash; including the letters you type. To do this, every character must be assigned a unique number, which is then stored as its binary equivalent. A <dfn class="term" data-def="A defined list that assigns a unique numerical code to each character a computer can store or display, including letters, digits, punctuation and control codes.">character set</dfn> is the agreed list that maps each character to its code. Without a shared standard, a file created on one system would display differently on another.</p>

<h2 data-narration-id="n3">7-Bit ASCII</h2>
<p data-narration-id="n4"><dfn class="term" data-def="American Standard Code for Information Interchange. A 7-bit character encoding standard representing 128 characters including the English alphabet (upper and lower case), digits 0&ndash;9, punctuation and control characters.">ASCII</dfn> (American Standard Code for Information Interchange) uses <strong>7 bits</strong> per character, allowing \(2^7 = 128\) unique codes (0 to 127). These 128 characters cover upper-case letters, lower-case letters, the digit characters 0&ndash;9, punctuation marks and control characters such as &ldquo;new line&rdquo;.</p>
<p data-narration-id="n5">The key principle is that codes are <strong>sequential within each group</strong>. Upper-case A&nbsp;=&nbsp;65, B&nbsp;=&nbsp;66, up to Z&nbsp;=&nbsp;90. Lower-case a&nbsp;=&nbsp;97, b&nbsp;=&nbsp;98, up to z&nbsp;=&nbsp;122. Digit character &lsquo;0&rsquo;&nbsp;=&nbsp;48, &lsquo;1&rsquo;&nbsp;=&nbsp;49, up to &lsquo;9&rsquo;&nbsp;=&nbsp;57. This sequential grouping means you can calculate any character&rsquo;s code if you know one code in the same group.</p>

<div class="key-fact" data-narration-id="n6" data-revision-tip="Cover this and recall from memory: what is the ASCII code for 'A'? For 'a'? For '0'? Now calculate the code for 'P' and for 'm'.">
  <div class="key-fact-label">Key Fact</div>
  <p>In ASCII: upper-case A&nbsp;=&nbsp;65; lower-case a&nbsp;=&nbsp;97; digit character &lsquo;0&rsquo;&nbsp;=&nbsp;48. Codes are sequential: &lsquo;P&rsquo;&nbsp;=&nbsp;65&nbsp;+&nbsp;15&nbsp;=&nbsp;80; &lsquo;m&rsquo;&nbsp;=&nbsp;97&nbsp;+&nbsp;12&nbsp;=&nbsp;109. ASCII uses 7 bits and represents 128 characters.</p>
</div>

<h2 data-narration-id="n10">Bitmap Images</h2>
<p data-narration-id="n11">Every digital image is built from a grid of tiny coloured squares called <dfn class="term" data-def="The smallest individual element of a digital image. Short for picture element.">pixels</dfn>. Each pixel stores a single colour value in binary. The total number of pixels is determined by the image&rsquo;s <strong>resolution</strong> &mdash; its width in pixels multiplied by its height in pixels.</p>
<p data-narration-id="n12"><dfn class="term" data-def="The number of bits used to represent the colour of each pixel. More bits means a greater range of possible colours.">Colour depth</dfn> determines how many different colours are available per pixel. With 1-bit colour depth, only 2 colours are possible. With 8-bit depth, \(2^8 = 256\) colours are possible. With 24-bit depth, over 16 million distinct colours can be represented, appearing photorealistic to the human eye.</p>

<div class="key-fact" data-narration-id="n13" data-revision-tip="Write the image file size formula from memory. Then use it: a 1280 pixel by 720 pixel image at 24-bit colour depth. Give your answer in bytes.">
  <div class="key-fact-label">Key Fact</div>
  <p>Image file size (bits) = width (pixels) &times; height (pixels) &times; colour depth (bits). To convert to bytes, divide by 8. Always state the unit explicitly &mdash; exam questions may ask for bits, bytes, or larger units.</p>
</div>

<h2 data-narration-id="n18">Sound Representation</h2>
<p data-narration-id="n19">Sound is an <dfn class="term" data-def="A signal that varies continuously over time, such as the pressure wave of a sound.">analogue signal</dfn> &mdash; a continuous wave of changing air pressure. Computers cannot store continuous signals directly. Instead, sound is digitised by taking regular measurements called <dfn class="term" data-def="A measurement of the amplitude (volume level) of a sound wave taken at a single point in time, recorded as a binary number.">samples</dfn>. Each sample captures the <strong>amplitude</strong> (volume level) at that instant.</p>

<h2 data-narration-id="n20">Sample Rate and Bit Depth</h2>
<p data-narration-id="n21"><dfn class="term" data-def="The number of samples taken per second when digitising sound, measured in hertz (Hz).">Sample rate</dfn> (also called sampling rate) is how many samples are taken per second, measured in hertz (Hz). A higher sample rate means more measurements per second, capturing the original wave more faithfully. The <strong>sample interval</strong> is the time between consecutive samples &mdash; it is the inverse of the sample rate. A sample rate of 44,100 Hz gives a sample interval of roughly 0.023 milliseconds.</p>
<p data-narration-id="n22"><dfn class="term" data-def="The number of bits used to store each individual sound sample, also called sample resolution. More bits means more precise volume levels.">Bit depth</dfn> (also called sample resolution) is the number of bits used to store each sample. More bits means more distinct amplitude levels can be recorded. At 16-bit depth, \(2^{16} = 65,536\) distinct volume levels are possible per sample.</p>

<div class="key-fact" data-narration-id="n23" data-revision-tip="Write the sound file size formula from memory, then calculate the size of a 5-second recording at 44,100 Hz and 16-bit depth. Give your answer in bytes.">
  <div class="key-fact-label">Key Fact</div>
  <p>Sound file size (bits) = sample rate (Hz) &times; bit depth (bits) &times; duration (seconds). To convert to bytes, divide by 8. Increasing either sample rate or bit depth improves quality but increases file size.</p>
</div>

<h2 data-narration-id="n27">Limitations of Binary Representation</h2>
<p data-narration-id="n28">When the number of available bits is limited, binary representation becomes less precise. In images, fewer bits per pixel means fewer possible colours and visible banding or &ldquo;colour blocking&rdquo; in graduated tones. In sound, a lower bit depth means fewer amplitude levels, producing audible distortion known as quantisation noise. A reduced sample rate may miss rapid sound-wave variations, causing high-frequency detail to be lost.</p>
<p data-narration-id="n29">These limitations represent the fundamental trade-off in data representation: more bits always means greater fidelity, but larger file sizes. Real systems manage this by choosing an appropriate bit width for the task &mdash; a voice call needs far less fidelity than a recording studio session.</p>

<h3 data-narration-id="n31">Key Takeaways</h3>
<ul>
  <li data-narration-id="n32">7-bit ASCII represents 128 characters. Codes are sequential: A=65, a=97, &lsquo;0&rsquo;=48. Calculate any code by counting from the group start.</li>
  <li data-narration-id="n33">Bitmap image file size (bits) = width &times; height &times; colour depth. Always state width and height in pixels.</li>
  <li data-narration-id="n34">Sound file size (bits) = sample rate &times; bit depth &times; duration. Higher values of either setting improve quality but increase file size. Fewer available bits reduce fidelity.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n30">Image file-size calculations are a reliable source of marks &mdash; but read the question carefully. State width and height in <strong>pixels</strong> (not &ldquo;dots&rdquo; or &ldquo;points&rdquo;) because the examiner expects the unit. If asked for the number of colours from colour depth \(d\), the answer is \(2^d\). For ASCII code calculations, always use the group starting point (A=65, a=97, &lsquo;0&rsquo;=48) and count from there &mdash; never guess.</p>
