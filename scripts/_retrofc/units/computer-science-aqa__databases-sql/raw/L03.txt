--- CONTENT_HTML ---
<h2 data-narration-id="n1">Modifying a Database</h2>
<p data-narration-id="n2">So far you have learnt to retrieve data with SELECT. Real databases also need to grow and change: new students join a school and need rows adding; contact details change and need updating; leavers&rsquo; records are eventually removed. SQL provides three commands for these operations: <dfn class="term" data-def="SQL command that adds a new row of data into a specified table.">INSERT INTO</dfn>, <dfn class="term" data-def="SQL command that modifies existing rows in a table, changing specified column values for rows matching a condition.">UPDATE</dfn>, and <dfn class="term" data-def="SQL command that removes rows from a table that match a specified condition.">DELETE FROM</dfn>. We use the same Students, Courses and Enrolments tables as before throughout all the examples in this lesson.</p>
<p data-narration-id="n3">Reminder of the schema:<br>
<strong>Students</strong> &mdash; student_id (PK), student_name, year_group<br>
<strong>Courses</strong> &mdash; course_id (PK), course_title<br>
<strong>Enrolments</strong> &mdash; enrolment_id (PK), student_id (FK), course_id (FK)</p>

<h2 data-narration-id="n4">INSERT INTO &mdash; Adding New Rows</h2>
<p data-narration-id="n5">To add a new record, use:</p>
<p data-narration-id="n6"><code>INSERT INTO table_name (column1, column2, &hellip;)<br>VALUES (value1, value2, &hellip;);</code></p>
<p data-narration-id="n7">The columns list and the values list must match in number and order. Text values go in single quotes; integers do not. You do not have to include every column &mdash; you can omit columns that have a default value or are auto-generated by the database (such as an auto-increment primary key).</p>

  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n8"><strong>Task:</strong> Add a new student, Dani Osei, in year group 10, with student_id 4.</p>
    <p data-narration-id="n9"><code>INSERT INTO Students (student_id, student_name, year_group)<br>VALUES (4, &lsquo;Dani Osei&rsquo;, 10);</code></p>
    <p data-narration-id="n10">After this query runs, the Students table gains a new row: <code>4 | Dani Osei | 10</code>. Notice that 4 (an integer) has no quotes, while &lsquo;Dani Osei&rsquo; (text) does.</p>
    <p data-narration-id="n11"><strong>Adding an enrolment record:</strong> To enrol Dani (student_id = 4) on course 2:</p>
    <p data-narration-id="n12"><code>INSERT INTO Enrolments (enrolment_id, student_id, course_id)<br>VALUES (10, 4, 2);</code></p>
    <p data-narration-id="n13">All three values are integers so none need quotes. The foreign key value (student_id = 4) must already exist in the Students table &mdash; you cannot enrol a student who doesn&rsquo;t exist.</p>

</div>

<h2 data-narration-id="n14">UPDATE &mdash; Changing Existing Data</h2>
<p data-narration-id="n15">To change data in existing rows, use:</p>
<p data-narration-id="n16"><code>UPDATE table_name<br>SET column1 = value1, column2 = value2, &hellip;<br>WHERE condition;</code></p>
<p data-narration-id="n17">The SET clause names the columns to change and their new values. The WHERE clause identifies <em>which rows</em> to update. You can update more than one column at once by separating them with commas in the SET clause.</p>

<div class="collapsible">
  <button class="collapsible-toggle" aria-expanded="false">
    <span>Worked Example 2 &mdash; UPDATE with WHERE</span>
    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>
  </button>
  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n18"><strong>Task:</strong> Change Aisha Khan&rsquo;s year group to 11.</p>
    <p data-narration-id="n19"><code>UPDATE Students<br>SET year_group = 11<br>WHERE student_name = &lsquo;Aisha Khan&rsquo;;</code></p>
    <p data-narration-id="n20">Only the row (or rows) where student_name equals &lsquo;Aisha Khan&rsquo; is changed. All other rows remain exactly as they were.</p>
    <p data-narration-id="n21"><strong>Updating two columns at once:</strong> Rename student_id 2 and move them to year 11.</p>
    <p data-narration-id="n22"><code>UPDATE Students<br>SET student_name = &lsquo;Benjamin Okafor&rsquo;, year_group = 11<br>WHERE student_id = 2;</code></p>
    <p data-narration-id="n23">Two columns are updated in a single query. Using student_id in the WHERE clause is safer than using student_name, because student_id is the primary key and uniquely identifies one row.</p>
  </div></div>
</div>

<div class="key-fact" data-narration-id="n24" data-revision-tip="Cover this and write from memory: what happens to an UPDATE query if you forget the WHERE clause entirely?">
  <div class="key-fact-label">Key Fact</div>
  <p><strong>Critical rule:</strong> An UPDATE without a WHERE clause changes <em>every single row</em> in the table. Writing <code>UPDATE Students SET year_group = 11;</code> would change all students&rsquo; year groups to 11, overwriting all existing data. Always include a WHERE clause to target only the intended rows.</p>
</div>

<h2 data-narration-id="n25">DELETE FROM &mdash; Removing Rows</h2>
<p data-narration-id="n26">To remove one or more rows from a table, use:</p>
<p data-narration-id="n27"><code>DELETE FROM table_name<br>WHERE condition;</code></p>
<p data-narration-id="n28">The WHERE clause identifies which rows to remove. Every row matching the condition is permanently deleted &mdash; this cannot be undone in a basic SQL query. If no WHERE clause is given, every row in the table is deleted.</p>

  <button class="collapsible-toggle" aria-expanded="false">
    <span>Worked Example 3 &mdash; DELETE FROM with WHERE</span>
    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>
  </button>
  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n29"><strong>Task:</strong> Remove the student with student_id 3 from the Students table.</p>
    <p data-narration-id="n30"><code>DELETE FROM Students<br>WHERE student_id = 3;</code></p>
    <p data-narration-id="n31">Only the row where student_id = 3 is deleted. Using the primary key in the WHERE clause ensures exactly one row is targeted.</p>
    <p data-narration-id="n32"><strong>Deleting an enrolment:</strong> Remove all enrolments for student_id 1.</p>
    <p data-narration-id="n33"><code>DELETE FROM Enrolments<br>WHERE student_id = 1;</code></p>
    <p data-narration-id="n34">If student 1 has three enrolment records, all three are deleted by this single query because all three rows satisfy the condition.</p>
  </div></div>
</div>

<div class="key-fact" data-narration-id="n35" data-revision-tip="Explain to someone: why is DELETE FROM Students; without a WHERE clause catastrophic, and how do you avoid this in practice?">
  <div class="key-fact-label">Key Fact</div>
  <p><strong>The WHERE clause on DELETE is never optional in practice.</strong> <code>DELETE FROM Students;</code> without a WHERE clause deletes every student record in the table &mdash; all data is lost. Always test a WHERE condition with a SELECT query first to confirm it targets the right rows, before running DELETE.</p>
</div>



<h2 data-narration-id="n36">Test Before You Modify</h2>
<p data-narration-id="n37">A good habit before running any UPDATE or DELETE on a real database is to first run a SELECT query with the same WHERE condition. If the SELECT returns exactly the rows you expected, you can be confident the UPDATE or DELETE will target the right records and no others. For example, before running DELETE FROM Students WHERE year_group = 10; first run SELECT * FROM Students WHERE year_group = 10; to review exactly which rows will be affected. This test-first approach is a practical way to prevent accidental data loss.</p>

<h2 data-narration-id="n38">Comparing the Three Commands</h2>
<p data-narration-id="n39">To summarise the three data-modification commands:</p>
<ul>
  <li data-narration-id="n40"><strong>INSERT INTO</strong> &mdash; adds one new row. Needs column names and matching values. Cannot target existing rows.</li>
  <li data-narration-id="n41"><strong>UPDATE&hellip;SET&hellip;WHERE</strong> &mdash; changes values in existing rows. Must use WHERE to target specific rows. Can update multiple columns in one query.</li>
  <li data-narration-id="n42"><strong>DELETE FROM&hellip;WHERE</strong> &mdash; removes whole rows. Must use WHERE to target specific rows. The deletion is immediate and permanent.</li>
</ul>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n44">Key Takeaways</h3>
<ul>
  <li data-narration-id="n45">INSERT INTO adds a new row: list column names, then matching values. Text values need single quotes; integers do not.</li>
  <li data-narration-id="n46">UPDATE changes existing rows: SET names the columns and new values, WHERE targets which rows. Without WHERE, every row is changed.</li>
  <li data-narration-id="n47">DELETE FROM removes rows: WHERE targets which rows. Without WHERE, every row is deleted. Always include WHERE &mdash; this is a non-negotiable safety rule.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n43">The most common error in SQL modification questions is writing an UPDATE or DELETE without a WHERE clause. Examiners will penalise this directly &mdash; and in some mark schemes, omitting WHERE on a DELETE question loses all marks because the command would wipe the entire table. For INSERT INTO, remember: the column list and value list must have the same number of items and be in the same order. If the question gives you a table schema, check the column names and data types before writing your answer.</p>
