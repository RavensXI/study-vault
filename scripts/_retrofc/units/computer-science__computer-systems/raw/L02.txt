--- DESCRIPTION ---
How clock speed, cache size and number of cores decide how fast a CPU works.

--- CONTENT_HTML ---
<p data-narration-id="n1">Two computers can look almost identical yet one feels far quicker than the other. The difference usually comes down to the <dfn class="term" data-def="The central processing unit &mdash; the component that fetches, decodes and executes program instructions.">CPU</dfn> and how fast it can work through the fetch-execute cycle. We call this its <em>performance</em>: roughly, how many instructions it can carry out each second. Three characteristics have the biggest effect on how well a CPU performs &mdash; its clock speed, the size of its cache, and its number of cores.</p><p data-narration-id="n2">Understanding each one, and how they combine, lets you explain why a gaming desktop outperforms a budget laptop, and why upgrading just one part of a system does not always give the speed boost you might expect.</p><h2 data-narration-id="n3">Clock speed</h2><p data-narration-id="n4">Inside every CPU is a clock that sends out a steady electrical pulse. Each pulse triggers the processor to carry out one step of its work. <dfn class="term" data-def="The number of cycles a CPU carries out each second, measured in hertz.">Clock speed</dfn> is the number of these pulses, or cycles, per second. It is measured in <dfn class="term" data-def="The unit for clock speed, equal to one cycle per second.">hertz</dfn> (Hz). Because modern processors are so fast, clock speed is usually given in gigahertz (GHz), where one gigahertz equals one billion cycles per second. A CPU running at 3.5 GHz completes 3.5 billion cycles every single second.</p><p data-narration-id="n5">As a rough guide, more cycles per second means more instructions carried out per second, so a higher clock speed usually gives better performance. Pushing a CPU beyond its factory clock speed is called <dfn class="term" data-def="Running a CPU faster than its factory clock speed to gain performance, which increases heat output.">overclocking</dfn>; it can raise speed but produces extra heat, which is why fast computers need effective cooling such as fans or heat sinks.</p><div class="key-fact" data-narration-id="n6" data-revision-tip="Cover this and write down: how many cycles per second does a 3.0 GHz CPU complete, and what unit is clock speed measured in?"><div class="key-fact-label">Key Fact</div><p>One gigahertz (GHz) means one billion clock cycles per second, so a 3.0 GHz CPU completes three billion cycles every second. Clock speed is measured in hertz.</p></div><h2 data-narration-id="n7">Cache size</h2><p data-narration-id="n8">Fetching data from the computer&rsquo;s main memory (RAM) takes time, and while the CPU waits it cannot do useful work. To cut this delay, the CPU contains a small amount of extremely fast memory called <dfn class="term" data-def="Small, very fast memory inside or very close to the CPU that stores frequently used data and instructions.">cache</dfn>. Cache holds copies of the data and instructions the CPU uses most often, right beside the processor where they can be reached almost instantly.</p><p data-narration-id="n9">When the CPU finds what it needs in the cache, this is a <dfn class="term" data-def="When the CPU finds the data or instruction it needs already stored in the cache.">cache hit</dfn>. When it does not, and has to fetch from slower RAM instead, this is a <dfn class="term" data-def="When the data the CPU needs is not in the cache, forcing a slower fetch from RAM.">cache miss</dfn>. A larger cache can hold more data, so more requests become cache hits and fewer slow trips to RAM are needed. That is why increasing the cache size improves performance.</p><div class="collapsible"><button class="collapsible-toggle" aria-expanded="false"><span>The three levels of cache</span><svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg></button><div class="collapsible-content"><div class="collapsible-inner"><p data-narration-id="n10">Cache is usually split into levels. <strong>L1 cache</strong> is the smallest and fastest, built right into the core. <strong>L2 cache</strong> is larger but slightly slower. <strong>L3 cache</strong> is the largest and slowest of the three, though still far faster than RAM. The CPU checks L1 first, then L2, then L3, and only goes out to RAM if the data is not in any level of cache.</p></div></div></div><div class="key-fact" data-narration-id="n11" data-revision-tip="Close this and explain in one sentence the difference between a cache hit and a cache miss."><div class="key-fact-label">Key Fact</div><p>Cache is small, fast memory inside the CPU that stores frequently used data and instructions. A cache hit avoids a slower trip to RAM; a larger cache produces more hits.</p></div><h2 data-narration-id="n12">Number of cores</h2><p data-narration-id="n13">A <dfn class="term" data-def="A complete processing unit inside the CPU that can run the fetch-execute cycle on its own.">core</dfn> is a complete processing unit inside the CPU that can run the fetch-execute cycle by itself. Early CPUs had a single core and could only work on one instruction at a time. Modern CPUs are usually multi-core &mdash; dual-core (two cores), quad-core (four) or even octa-core (eight) &mdash; with several cores built onto one chip.</p><p data-narration-id="n14">Having more cores lets a CPU carry out <dfn class="term" data-def="Using several cores to work on different instructions at the same time.">parallel processing</dfn>: different cores work on different instructions at the same moment. In theory a quad-core CPU can handle four sets of instructions at once, which is a real advantage when running several programs together, or one program written to share its work across cores.</p><div class="collapsible"><button class="collapsible-toggle" aria-expanded="false"><span>Why twice the cores does not mean twice the speed</span><svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg></button><div class="collapsible-content"><div class="collapsible-inner"><p data-narration-id="n15">More cores only help if the software is written to split its work into parts that can run at the same time. Some tasks are sequential &mdash; each step depends on the result of the last &mdash; and cannot be shared out, so they run no faster on eight cores than on one. Cores also share resources such as memory, so doubling the number of cores rarely doubles real-world performance.</p></div></div></div><h2 data-narration-id="n16">How the three work together</h2><p data-narration-id="n17">These characteristics affect performance both individually and in combination. A CPU with a very high clock speed but a tiny cache may keep stalling while it waits for data from RAM. Adding more cores helps with several tasks at once but does little for a single, simple job that only uses one core. The strongest processors balance all three: a fast clock, a generous cache and several cores.</p><p data-narration-id="n18">There are trade-offs, too. Higher clock speeds and extra cores both draw more electrical power and give off more heat, which matters in laptops and phones where battery life and cooling are limited. Designers pick the balance that suits the device, which is why the CPU in a desktop gaming PC is built very differently from the chip in a smartphone.</p>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n20">Key Takeaways</h3><ul><li data-narration-id="n21">Clock speed is how many cycles per second a CPU performs, measured in gigahertz; a higher clock speed usually means more instructions carried out each second.</li><li data-narration-id="n22">Cache is small, fast memory inside the CPU; a larger cache means more cache hits and fewer slow trips to main memory.</li><li data-narration-id="n23">More cores allow parallel processing, but only benefit tasks and software that can be split across them.</li></ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n19">When a question asks you to <strong>explain</strong> how a characteristic affects performance, always give the reason as well as the effect &mdash; for example, &lsquo;a larger cache stores more data, so there are more cache hits and fewer slow trips to RAM, which speeds the CPU up&rsquo;. For higher-mark &lsquo;discuss&rsquo; questions, weigh up more than one characteristic and remember that extra cores only help software that is written to use them.</p>
