=== L9 Networks, Topologies & Protocols ===

--- DESCRIPTION ---
How networks are built and shaped, and the rules and addresses that move data between them.

--- CONTENT_HTML ---
<p data-narration-id="n1">A network is two or more computers or devices connected together so that they can share data and resources such as files, printers and a single internet connection. Almost everything you do online depends on networks, so it helps to understand how they are built and the rules that let different devices work together.</p><p data-narration-id="n2">Networks are grouped by the area they cover. A <dfn class="term" data-def="A network that covers a small geographical area on a single site, such as a school, home or office.">Local Area Network (LAN)</dfn> covers a small area on a single site, such as a school, home or office, and the organisation that runs it usually owns all of the hardware and cabling. A <dfn class="term" data-def="A network that covers a large geographical area and connects LANs together; the internet is the largest example.">Wide Area Network (WAN)</dfn> covers a large area and joins together LANs that may be in different towns, countries or even continents. Because a WAN stretches over such distances, its infrastructure is often leased from telecommunications companies rather than owned outright. The internet is the largest WAN of all.</p><div class="key-fact" data-narration-id="n3" data-revision-tip="Cover this and state one difference between a LAN and a WAN, then give an example of each."><div class="key-fact-label">Key Fact</div><p>A LAN covers a small area on one site and is owned by the organisation that runs it; a WAN covers a large area, connects LANs together, and usually relies on leased infrastructure. The internet is the largest WAN.</p></div><p data-narration-id="n4">The speed a network feels to its users depends on several factors. The most important is <dfn class="term" data-def="The maximum amount of data a connection can carry in a given time, usually measured in bits per second.">bandwidth</dfn>, which is the maximum amount of data a connection can carry in a given time. The more devices that are connected at once, the more they must share that bandwidth, so each device can slow down. Performance is also affected by whether a connection is wired or wireless, the quality of the cabling, and the amount of interference.</p><p data-narration-id="n5">Computers can take different roles on a network. In a <dfn class="term" data-def="A network where central servers provide services and resources that client computers request.">client-server</dfn> network, one or more powerful central computers called servers provide services, while the other computers, the clients, request them. This makes security, updates and backups easy to manage from one place, but the server is expensive and, if it fails, every client loses access. In a <dfn class="term" data-def="A network where all computers are equal and each can act as both a client and a server.">peer-to-peer</dfn> network the computers are all equal and each can act as both client and server, sharing files directly. This is cheaper and simpler for a small home network, but it is harder to back up and secure, and it slows down as more peers are added.</p><div class="collapsible"><button class="collapsible-toggle" aria-expanded="false"><span>Hardware that builds a LAN</span><svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg></button><div class="collapsible-content"><div class="collapsible-inner"><p data-narration-id="n6">Turning stand-alone computers into a working LAN needs several pieces of hardware, each with its own job:</p><ul><li data-narration-id="n7">A <dfn class="term" data-def="The hardware component that lets a device connect to a network and which carries the device&rsquo;s MAC address.">Network Interface Controller (NIC)</dfn> lets a single device connect to a network and gives it its MAC address.</li><li data-narration-id="n8">A switch connects devices together inside one LAN and uses their MAC addresses to send data only to the device it is meant for.</li><li data-narration-id="n9">A router connects different networks together, such as joining a home LAN to the internet, and directs data between them using IP addresses.</li><li data-narration-id="n10">A wireless access point lets wireless devices join a wired network over Wi-Fi.</li><li data-narration-id="n11">The transmission media are the cables or signals that actually carry the data, such as copper cable, fibre-optic cable or radio waves.</li></ul></div></div></div><p data-narration-id="n12">The internet is a worldwide collection of computer networks &mdash; a network of networks &mdash; all connected together. To find the computer that stores a particular website, your device uses the <dfn class="term" data-def="The system of servers that translates a domain name into the IP address of the computer that stores a website.">Domain Name System (DNS)</dfn>, which is made up of many separate domain name servers. When you type a web address, the DNS looks up the matching <dfn class="term" data-def="A number that identifies a device on a network and is used to route data between networks.">IP address</dfn> so your browser knows which server to connect to. If the first server does not hold that record, the request is simply passed on to another.</p><div class="key-fact" data-narration-id="n13" data-revision-tip="Close this and explain in one sentence what the DNS does when you type a web address."><div class="key-fact-label">Key Fact</div><p>The DNS turns a human-friendly web address into the IP address of the server that hosts the website, so your browser can connect to it.</p></div><p data-narration-id="n14">Websites and files are kept available through <dfn class="term" data-def="Storing files or websites on a server that is connected to the internet so they can be accessed at any time.">hosting</dfn>, where a company stores them on a server that stays connected to the internet all day, every day; a web server then sends those pages to any client that requests them. Many services are now delivered through <dfn class="term" data-def="The remote provision of storage, software or processing power over the internet instead of on a local machine.">cloud</dfn> computing, which means storage, software and processing are provided remotely over the internet instead of running on your own machine.</p><p data-narration-id="n15">The cloud lets people work from anywhere, avoids the cost of maintaining local hardware, and can back data up automatically. Its drawbacks are that it depends on a reliable internet connection, charges an ongoing subscription, and raises concerns about the security of data held by someone else.</p><p data-narration-id="n16">The <dfn class="term" data-def="The shape or arrangement in which the devices on a network are connected together.">topology</dfn> of a network describes the shape in which its devices are arranged. In a <dfn class="term" data-def="A topology where every device has its own cable connecting it to a central switch.">star topology</dfn> every device has its own cable to a central switch. In a <dfn class="term" data-def="A topology where devices connect to many others so data can travel by more than one route.">mesh topology</dfn> devices are connected to many others so that data can travel by more than one route.</p><div class="collapsible"><button class="collapsible-toggle" aria-expanded="false"><span>Comparing star and mesh topologies</span><svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg></button><div class="collapsible-content"><div class="collapsible-inner"><p data-narration-id="n17">A star topology gives each device a dedicated connection, so there are few collisions and performance is good, and if one cable fails only that single device is cut off. Its weakness is that the whole network depends on the central switch: if the switch fails, everything stops, and the design needs a lot of cabling.</p><p data-narration-id="n18">A mesh topology has no single point of failure, because if one link breaks the data simply takes another route, which makes it very reliable and good at handling heavy traffic. The drawback is that a fully wired mesh needs a huge amount of cabling and is expensive and complex to set up, which is why mesh networks are often built wirelessly.</p></div></div></div><p data-narration-id="n19">Devices connect either by a wired link, usually an <dfn class="term" data-def="A widely used standard for wired network connections.">Ethernet</dfn> cable, or wirelessly through Wi-Fi or Bluetooth. A wired connection is faster, more stable and more secure, because an intruder needs physical access to the cable, but it ties devices down and costs more to install. A wireless connection is convenient and lets devices move around freely, but it is usually slower, can suffer interference and dropouts, and is easier to intercept. Bluetooth is a short-range wireless link used to connect personal devices such as headphones or a keyboard.</p><p data-narration-id="n20">Because data can be intercepted as it crosses a network, it is often protected by <dfn class="term" data-def="Scrambling data using a key so that only the intended recipient can read it.">encryption</dfn>, which scrambles the data using a key so that anyone who intercepts it sees only meaningless characters; only the intended recipient, who holds the key, can turn it back into the original message.</p><p data-narration-id="n21">Every device also needs an address so that data reaches the right place. An IP address identifies a device on a network and is used to route data between networks. Older IPv4 addresses are 32 bits long and are written as four numbers from 0 to 255 separated by dots, such as 192.168.0.1; because the world is running out of these, newer IPv6 addresses are 128 bits long and are written as groups of hexadecimal digits. A <dfn class="term" data-def="A permanent address built into a device&rsquo;s network card by its manufacturer, used to identify it on a local network.">MAC address</dfn>, by contrast, is a permanent number built into a device&rsquo;s network card by its manufacturer, written as twelve hexadecimal digits, and is used to identify a device within a local network.</p><p data-narration-id="n22">For devices made by different companies to work together, everyone must follow the same agreed rules, called <dfn class="term" data-def="Agreed rules that allow hardware and software from different manufacturers to work together.">standards</dfn>. Without standards, equipment made by one company might not work with equipment made by another. Familiar examples include the agreed character set used to store text and the language used to build web pages.</p><p data-narration-id="n23">A <dfn class="term" data-def="A set of rules that controls how data is transferred between devices.">protocol</dfn> is a set of rules that controls how data is transferred between devices, covering things like the format of the data and the order in which messages are sent. Because different jobs need different rules, there are several protocols, each with its own purpose.</p><div class="collapsible"><button class="collapsible-toggle" aria-expanded="false"><span>Common protocols and what they do</span><svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg></button><div class="collapsible-content"><div class="collapsible-inner"><p data-narration-id="n24">Each of these protocols has a specific job:</p><ul><li data-narration-id="n25"><strong>TCP/IP</strong> is the core set of rules for the internet: it breaks data into packets, addresses them, routes them across networks and reassembles them at the far end.</li><li data-narration-id="n26"><strong>HTTP</strong> (Hypertext Transfer Protocol) is used to transfer web pages between a web server and a browser.</li><li data-narration-id="n27"><strong>HTTPS</strong> is the secure version of HTTP, which encrypts the data and is used for logins and payments.</li><li data-narration-id="n28"><strong>FTP</strong> (File Transfer Protocol) is used to upload and download files to and from a server.</li><li data-narration-id="n29"><strong>POP</strong> (Post Office Protocol) retrieves emails from a mail server, usually downloading them to one device and removing them from the server.</li><li data-narration-id="n30"><strong>IMAP</strong> (Internet Message Access Protocol) manages emails while keeping them on the server, so they can be read from several devices.</li><li data-narration-id="n31"><strong>SMTP</strong> (Simple Mail Transfer Protocol) sends emails and passes them between mail servers.</li></ul></div></div></div><p data-narration-id="n32">To keep all of these rules manageable, protocols are organised into <dfn class="term" data-def="Self-contained sections into which network protocols are organised, each handling one part of the communication.">layers</dfn>. Each layer deals with just one part of the communication and only has to work with the layers directly above and below it. This means different teams can develop different layers, a layer can be improved or replaced without breaking the others, and faults are easier to track down. A common teaching model splits the whole process into four such layers.</p>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n34">Key Takeaways</h3><ul><li data-narration-id="n35">A LAN covers one site and is owned by its organisation, while a WAN covers a large area and connects LANs; the internet is the largest WAN.</li><li data-narration-id="n36">The DNS turns a web address into an IP address; a switch moves data within a LAN using MAC addresses, and a router moves data between networks using IP addresses.</li><li data-narration-id="n37">Protocols are agreed sets of rules, such as HTTP for web pages and SMTP for sending email, and they are organised into layers to keep them manageable.</li></ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n33">Read the command word carefully: &lsquo;state&rsquo; or &lsquo;identify&rsquo; wants a short answer for one mark, while &lsquo;describe&rsquo; and &lsquo;explain&rsquo; want you to add detail and reasons. A very common mistake is mixing up the switch and the router &mdash; remember that a switch moves data within a LAN using MAC addresses, while a router moves data between networks using IP addresses. Keep the two kinds of address straight too: a MAC address is permanent, but an IP address can change.</p>
