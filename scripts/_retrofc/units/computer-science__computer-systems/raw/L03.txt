--- DESCRIPTION ---
What embedded systems are, why everyday devices use them, and how they differ from PCs.

--- CONTENT_HTML ---
<h2 data-narration-id="n1">What Is an Embedded System?</h2>
<p data-narration-id="n2">An <dfn class="term" data-def="A computer built into a larger device to perform one dedicated task.">embedded system</dfn> is a computer built into a larger device to carry out one <dfn class="term" data-def="The single, fixed task that an embedded system is designed to perform.">dedicated function</dfn>. Unlike a laptop, you do not sit down and type at it &mdash; it sits hidden inside a product, quietly controlling how that product works. A washing machine is a good example: a small computer inside it reads the buttons you press, then switches the water, drum motor and heater on and off in the right order to run your chosen wash. That computer only ever runs the washing programme. It cannot browse the web, play games or run a word processor, because it was designed to do one job and do it well.</p>

<div class="key-fact" data-narration-id="n3" data-revision-tip="Cover this and write your own one-sentence definition of an embedded system, then name two devices that contain one.">
  <div class="key-fact-label">Key Fact</div>
  <p>An embedded system is a computer that is part of a larger device and is designed to perform a single dedicated task, such as controlling a washing machine or a microwave.</p>
</div>

<h2 data-narration-id="n4">What Is Inside an Embedded System?</h2>
<p data-narration-id="n5">At the heart of most embedded systems is a <dfn class="term" data-def="A single chip that combines a processor, memory and input/output connections.">microcontroller</dfn> &mdash; a single chip that combines a processor, a small amount of memory and input/output connections in one package. Putting everything on one chip keeps the device small and cheap. The program the microcontroller runs is called <dfn class="term" data-def="The permanent program that controls an embedded system, usually stored in read-only memory.">firmware</dfn>, and it is usually stored in read-only memory so that it is ready the moment the device is switched on and is not lost when the power is turned off.</p>
<p data-narration-id="n6">Because the device only has to do one job, designers give it just enough processing power and memory to do that job &mdash; no more. A microwave&rsquo;s controller does not need the power of a desktop PC, so fitting a large, expensive processor would only waste money and energy. This &lsquo;just enough&rsquo; approach is one of the main reasons embedded systems are so cheap to make in huge numbers.</p>

    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>

  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n7">On a laptop you install and delete programs all the time &mdash; software is meant to change. Firmware is different: it is written once for the device and normally stays the same for the product&rsquo;s whole life. Some modern products, such as smart TVs and routers, do let their firmware be updated to fix bugs or add features, but for most simple appliances the firmware is fixed and the user never changes it.</p>
  </div></div>
</div>

<h2 data-narration-id="n8">Typical Characteristics</h2>
<p data-narration-id="n9">Embedded systems share a recognisable set of features. They are <strong>dedicated</strong> to one task, <strong>small</strong> enough to fit inside another product, <strong>low-powered</strong> so they run cool and cheaply, and <strong>low-cost</strong> because they are produced in huge numbers. They are also built to be <strong>reliable</strong>: a pacemaker or a car braking system must work perfectly every time, so the hardware and firmware are kept simple and thoroughly tested.</p>
<p data-narration-id="n10">Many embedded systems are also <dfn class="term" data-def="A system that must respond to its inputs immediately, without any noticeable delay.">real-time system</dfn>s, meaning they must respond to inputs straight away rather than after a delay. When a car&rsquo;s anti-lock braking system senses a wheel starting to lock, it has to react in a fraction of a second &mdash; a late response would be useless. Reacting instantly and predictably is often more important for these systems than raw processing speed.</p>

<div class="key-fact" data-narration-id="n11" data-revision-tip="Close this and list five typical characteristics of an embedded system from memory.">
  <div class="key-fact-label">Key Fact</div>
  <p>Typical embedded systems are dedicated to one function, small, low-cost, low-power and highly reliable &mdash; and many must respond in real time.</p>
</div>

<div class="collapsible">
  <button class="collapsible-toggle" aria-expanded="false">
    <span>Why manufacturers choose embedded systems</span>
    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>
  </button>
  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n12">Using an embedded system instead of fitting a full computer brings clear benefits. Because the hardware only does one job, it can be made smaller, cheaper and more energy-efficient, and there is less that can go wrong, so it is more reliable. The trade-off is flexibility: an embedded system cannot easily be upgraded or given new tasks, and if the firmware has a fault it can be hard to fix once the product has been sold.</p>
  </div></div>
</div>

<h2 data-narration-id="n13">Examples of Embedded Systems</h2>
<p data-narration-id="n14">Embedded systems are all around you, usually without you noticing. In the home they control washing machines, dishwashers, microwaves and central-heating thermostats. In transport they run the engine-management and anti-lock braking systems in cars, and the controllers inside traffic lights. In healthcare they power devices such as pacemakers. In leisure and personal technology they appear in digital cameras, fitness trackers and MP3 players. In every case the same idea applies: a computer is built into the product to control one specific set of tasks.</p>

<h2 data-narration-id="n15">Embedded vs General-Purpose Computers</h2>
<p data-narration-id="n16">A <dfn class="term" data-def="A computer designed to run many different programs, such as a desktop PC, laptop or smartphone.">general-purpose computer</dfn>, such as a desktop PC, laptop, tablet or smartphone, is designed to run many different programs. You can install new software, delete it, and use the same machine for writing, gaming, video calls and browsing. It has a full operating system, plenty of memory and storage, and is built to be upgraded over time.</p>
<p data-narration-id="n17">An embedded system is the opposite. Its function is fixed when it is manufactured, its firmware is not meant to be changed by the user, and it usually has only the memory and processing power its single task requires. In short, a general-purpose computer is a flexible machine you adapt to many jobs, while an embedded system is a specialised machine dedicated to just one.</p>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n19">Key Takeaways</h3>
<ul>
<li data-narration-id="n20">An embedded system is a computer built into a larger device to perform one dedicated task, usually based around a microcontroller running fixed firmware.</li>
<li data-narration-id="n21">Typical embedded systems are dedicated, small, low-cost, low-power and reliable, and many are real-time systems that must respond immediately.</li>
<li data-narration-id="n22">A general-purpose computer runs many different, upgradeable programs, while an embedded system does one fixed job it was designed and manufactured for.</li>
</ul>
