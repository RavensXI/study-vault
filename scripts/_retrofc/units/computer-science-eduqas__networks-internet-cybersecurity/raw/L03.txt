--- CONTENT_HTML ---
<h2 data-narration-id="n1">Why Layered Models Exist</h2>
<p data-narration-id="n2">Sending data across a network involves dozens of different tasks: converting a file to electrical signals, addressing packets, establishing connections, encrypting data, and presenting information on screen. The <dfn class="term" data-def="A conceptual framework developed by the International Organisation for Standardisation that divides network communication into seven distinct layers, each with a specific responsibility.">OSI model</dfn> (Open Systems Interconnection model) organises these tasks into seven separate layers. Each layer has a clearly defined job and only needs to communicate with the layers directly above and below it. This makes networks easier to design, troubleshoot and develop: engineers can update one layer without rewriting the rest.</p>
<p data-narration-id="n3">The 2024 examiners&rsquo; report highlighted OSI layer descriptions as a weak area &mdash; students could name layers but not describe what each one does. This lesson focusses on function, not just naming. A common mnemonic for the layers from bottom to top: <strong>Please Do Not Throw Sausage Pizza Away</strong> (Physical, Data Link, Network, Transport, Session, Presentation, Application).</p>

<div class="key-fact" data-narration-id="n4" data-revision-tip="Cover this and write the seven OSI layers in order from layer 1 to layer 7, then add one word describing what each layer is responsible for.">
  <div class="key-fact-label">Key Fact</div>
  <p>The seven OSI layers from bottom to top are: Physical (1), Data Link (2), Network (3), Transport (4), Session (5), Presentation (6), Application (7). The mnemonic &ldquo;Please Do Not Throw Sausage Pizza Away&rdquo; helps you recall the correct order.</p>
</div>

<h2 data-narration-id="n5">Layer 1 &mdash; Physical</h2>
<p data-narration-id="n6">The <strong>Physical layer</strong> is responsible for transmitting raw <strong>bits</strong> (0s and 1s) over a physical medium &mdash; copper cable, fibre-optic cable or radio waves. It defines the electrical signals, voltages, connector types and timing used to represent binary data. The Physical layer has no concept of structure or meaning; it simply transmits and receives signals.</p>
<p data-narration-id="n7">Protocols and standards at this layer include <strong>Ethernet (cabling)</strong> and <strong>IEEE 802.11 (Wi-Fi radio)</strong>. Hardware at this layer includes cables, repeaters and hubs.</p>

<h2 data-narration-id="n8">Layer 2 &mdash; Data Link</h2>
<p data-narration-id="n9">The <dfn class="term" data-def="OSI layer 2, responsible for node-to-node delivery of frames within a network, using MAC addresses for addressing and error detection.">Data Link layer</dfn> takes the raw bits from the Physical layer and organises them into <strong>frames</strong>. It handles node-to-node delivery within a single network segment, using <strong>MAC addresses</strong> to identify source and destination. The Data Link layer also performs basic error detection (not correction) to check whether a frame arrived without corruption.</p>
<p data-narration-id="n10">Protocols at this layer include <strong>Ethernet</strong> (the framing standard for wired LANs) and <strong>Wi-Fi (IEEE 802.11)</strong>. Hardware: switches and bridges operate at this layer.</p>

<h2 data-narration-id="n11">Layer 3 &mdash; Network</h2>
<p data-narration-id="n12">The <dfn class="term" data-def="OSI layer 3, responsible for logical addressing and routing packets across multiple networks using IP addresses.">Network layer</dfn> is responsible for routing data across multiple networks from source to destination. It uses <strong>IP addresses</strong> (logical addresses) to identify devices globally and selects the best path for each packet. The data unit at this layer is a <strong>packet</strong>.</p>
<p data-narration-id="n13">The key protocol at this layer is <strong>IP</strong> (Internet Protocol). Hardware: routers operate at this layer, reading IP addresses to decide where to forward each packet.</p>

<h2 data-narration-id="n14">Layer 4 &mdash; Transport</h2>
<p data-narration-id="n15">The <dfn class="term" data-def="OSI layer 4, responsible for end-to-end communication between applications, providing reliable or unreliable delivery and managing flow control and error recovery.">Transport layer</dfn> manages end-to-end communication between applications on different hosts. It breaks data into <strong>segments</strong> and ensures they are reassembled correctly at the destination. It also handles <strong>flow control</strong> (preventing a fast sender from overwhelming a slow receiver) and <strong>error recovery</strong> (requesting retransmission of lost segments).</p>
<p data-narration-id="n16">Two key protocols operate here:</p>
<ul>
  <li data-narration-id="n17"><strong>TCP (Transmission Control Protocol)</strong> &mdash; connection-oriented. Before data is sent, TCP establishes a connection with a three-way handshake and guarantees delivery by acknowledging every segment. Used where accuracy matters: web pages (HTTP), email (SMTP), file transfer (FTP).</li>
  <li data-narration-id="n18"><strong>UDP (User Datagram Protocol)</strong> &mdash; connectionless. Segments are sent without acknowledgement, so UDP is faster but unreliable. Used where speed matters more than accuracy: video streaming, online gaming, voice calls.</li>
</ul>

<div class="key-fact" data-narration-id="n19" data-revision-tip="Close this and explain in two sentences: what is the difference between TCP and UDP, and give one application that uses each.">
  <div class="key-fact-label">Key Fact</div>
  <p>TCP (Transport layer) guarantees reliable, ordered delivery by acknowledging every segment &mdash; used by HTTP, SMTP and FTP. UDP sends segments without acknowledgement for speed &mdash; used by video streaming and online gaming. Both are Transport layer protocols.</p>
</div>

<h2 data-narration-id="n20">Layer 5 &mdash; Session</h2>
<p data-narration-id="n21">The <strong>Session layer</strong> establishes, manages and terminates sessions (conversations) between applications. A session is an ongoing exchange: for example, a video call between two computers involves a session that keeps both sides synchronised. The Session layer also provides checkpointing &mdash; if a large data transfer fails midway, the transfer can resume from the last checkpoint rather than restarting from scratch.</p>

<h2 data-narration-id="n22">Layer 6 &mdash; Presentation</h2>
<p data-narration-id="n23">The <strong>Presentation layer</strong> is responsible for translating data between the format the application uses and the format the network requires. Its three main tasks are <strong>data translation</strong> (converting character encodings, for example between UTF-8 and ASCII), <strong>data compression</strong> (reducing size before transmission) and <strong>encryption</strong> (scrambling data for secure transmission). HTTPS encryption (TLS/SSL) is handled at this layer.</p>

<h2 data-narration-id="n24">Layer 7 &mdash; Application</h2>
<p data-narration-id="n25">The <dfn class="term" data-def="OSI layer 7, the topmost layer, which provides network services directly to end-user applications such as web browsers and email clients.">Application layer</dfn> is the topmost layer and the one users interact with directly. It provides the interface between the network and the software applications running on a device. This is where user-facing <strong>protocols</strong> operate.</p>
<p data-narration-id="n26">Key Application layer protocols:</p>
<ul>
  <li data-narration-id="n27"><strong>HTTP</strong> (Hypertext Transfer Protocol) &mdash; transfers web pages between a server and a browser.</li>
  <li data-narration-id="n28"><strong>HTTPS</strong> (HTTP Secure) &mdash; HTTP with TLS encryption; used for secure web browsing and online transactions.</li>
  <li data-narration-id="n29"><strong>FTP</strong> (File Transfer Protocol) &mdash; transfers files between a client and a server.</li>
  <li data-narration-id="n30"><strong>SMTP</strong> (Simple Mail Transfer Protocol) &mdash; sends email from a client to a mail server or between mail servers.</li>
  <li data-narration-id="n31"><strong>POP3 / IMAP</strong> &mdash; retrieve email from a server. POP3 downloads and deletes from the server; IMAP keeps mail on the server and synchronises across devices.</li>
  <li data-narration-id="n32"><strong>DNS</strong> (Domain Name System) &mdash; translates human-readable domain names (e.g. studyvault.co.uk) into IP addresses.</li>
  <li data-narration-id="n33"><strong>DHCP</strong> (Dynamic Host Configuration Protocol) &mdash; automatically assigns IP addresses to devices joining a network.</li>
</ul>

    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>

    <p data-narration-id="n35"><strong>Misconception 1: &ldquo;HTTP is at the Transport layer.&rdquo;</strong> HTTP is an Application layer protocol. The Transport layer is where TCP and UDP operate &mdash; HTTP runs on top of TCP at the Application layer.</p>
    <p data-narration-id="n36"><strong>Misconception 2: &ldquo;Routers work at the Data Link layer.&rdquo;</strong> Routers operate at the Network layer (layer 3), reading IP addresses. Switches operate at the Data Link layer (layer 2), reading MAC addresses.</p>
    <p data-narration-id="n37"><strong>Misconception 3: &ldquo;Encryption happens at the Application layer.&rdquo;</strong> Encryption is primarily a Presentation layer function (layer 6). TLS/SSL, used for HTTPS, is a Presentation layer service even though it is triggered by an Application layer protocol.</p>
  </div></div>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n39">Key Takeaways</h3>
<ul>
  <li data-narration-id="n40">The OSI model has seven layers (Physical, Data Link, Network, Transport, Session, Presentation, Application) &mdash; each has a specific responsibility, making networks easier to design and troubleshoot.</li>
  <li data-narration-id="n41">Key protocols by layer: IP at Network (3); TCP/UDP at Transport (4); HTTP, HTTPS, FTP, SMTP, DNS and DHCP at Application (7); Ethernet and Wi-Fi at Data Link (2).</li>
  <li data-narration-id="n42">TCP guarantees reliable, ordered delivery and is used by web and email protocols; UDP is faster but unreliable and is used for streaming and gaming.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n38">The most common OSI exam question asks you to &ldquo;describe the function of layer X&rdquo; or &ldquo;state which layer protocol Y operates at&rdquo;. Simply naming the layer scores partial credit; describing what it does scores full marks. Practise writing one sentence per layer that begins with a verb: &ldquo;The Transport layer manages end-to-end communication between applications, guaranteeing delivery (TCP) or trading reliability for speed (UDP).&rdquo; Also remember: routers = Network layer (IP); switches = Data Link layer (MAC). This distinction appears regularly.</p>
