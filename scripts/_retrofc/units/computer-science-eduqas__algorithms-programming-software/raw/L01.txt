--- CONTENT_HTML ---
<h2 data-narration-id="n1">What Is an Algorithm?</h2>
<p data-narration-id="n2">An <dfn class="term" data-def="A precise, step-by-step set of instructions for solving a problem or carrying out a task.">algorithm</dfn> is a precise, step-by-step set of instructions for solving a problem. Every program you have ever run began as an algorithm. Before any code is written, a programmer must first design the logical steps the computer needs to follow. Getting those steps right &mdash; in the right order, with the right decisions &mdash; is the foundation of good software.</p>
<p data-narration-id="n3">Algorithms are not the same as programs. A program is a specific implementation in a specific language. An algorithm is language-independent &mdash; the same logic can be expressed in pseudocode, as a flowchart, or as code in Python, Java or any other language. Your exam tests whether you can design, trace and evaluate algorithms, regardless of which language you prefer to code in.</p>

<div class="key-fact" data-narration-id="n4" data-revision-tip="Cover this and write down the three properties a good algorithm must have. Check your wording against the definition.">
  <div class="key-fact-label">Key Fact</div>
  <p>A good algorithm must be <strong>unambiguous</strong> (each step has exactly one interpretation), <strong>finite</strong> (it must eventually stop), and <strong>effective</strong> (it must actually solve the problem it was designed for).</p>
</div>

<h2 data-narration-id="n5">Pseudocode</h2>
<p data-narration-id="n6"><dfn class="term" data-def="An informal, structured way of describing an algorithm using plain English mixed with programming-style keywords.">Pseudocode</dfn> is an informal notation that sits halfway between plain English and a real programming language. It is precise enough to be translated directly into code, but readable enough that a non-programmer can follow the logic. Your exam uses a set of specific pseudocode conventions &mdash; learn them so your algorithms are unambiguous.</p>
<p data-narration-id="n7">The key pseudocode keywords you need are shown below. Notice how they map to real programming ideas:</p>

<table data-narration-id="n8">
  <thead><tr><th>Purpose</th><th>Pseudocode keyword</th><th>Example</th></tr></thead>
  <tbody>
    <tr><td>Assignment</td><td><code>SET</code></td><td><code>SET total = 0</code></td></tr>
    <tr><td>Output to screen</td><td><code>OUTPUT</code></td><td><code>OUTPUT &ldquo;Hello&rdquo;</code></td></tr>
    <tr><td>Input from user</td><td><code>RECEIVE</code></td><td><code>RECEIVE name FROM (STRING)</code></td></tr>
    <tr><td>Conditional</td><td><code>IF / ELSE / END IF</code></td><td><code>IF score &gt; 50 THEN</code></td></tr>
    <tr><td>Count-controlled loop</td><td><code>FOR / NEXT</code></td><td><code>FOR i = 1 TO 10</code></td></tr>
    <tr><td>Condition-controlled loop</td><td><code>WHILE / END WHILE</code></td><td><code>WHILE total &lt; 100</code></td></tr>
    <tr><td>Post-condition loop</td><td><code>REPEAT / UNTIL</code></td><td><code>REPEAT ... UNTIL done = TRUE</code></td></tr>
    <tr><td>Define subroutine</td><td><code>PROCEDURE / END PROCEDURE</code></td><td><code>PROCEDURE greet(name)</code></td></tr>
    <tr><td>Define function</td><td><code>FUNCTION / END FUNCTION</code></td><td><code>FUNCTION square(n)</code></td></tr>
    <tr><td>Return a value</td><td><code>RETURN</code></td><td><code>RETURN result</code></td></tr>
  </tbody>
</table>

    <span>Worked Example: Pseudocode for Averaging Three Numbers</span>
    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>

    <p data-narration-id="n9">Below is a complete pseudocode algorithm that asks the user for three numbers and outputs their average. Each line maps directly to a keyword in the table above.</p>
    <pre data-narration-id="n10"><code>RECEIVE num1 FROM (INTEGER)
RECEIVE num2 FROM (INTEGER)
RECEIVE num3 FROM (INTEGER)
SET total = num1 + num2 + num3
SET average = total / 3
OUTPUT &ldquo;The average is &rdquo; &amp; average</code></pre>
    <p data-narration-id="n11">Notice: <code>RECEIVE</code> handles input, <code>SET</code> handles assignment, and <code>OUTPUT</code> sends text to the screen. The <code>&amp;</code> operator joins (concatenates) a string and a number in the output.</p>

<h2 data-narration-id="n12">Flowcharts</h2>
<p data-narration-id="n13">A <dfn class="term" data-def="A visual diagram using standard symbols to represent the steps and flow of control in an algorithm.">flowchart</dfn> shows exactly the same logic as pseudocode but as a visual diagram. Each shape has a fixed meaning. Arrows show the <dfn class="term" data-def="The order in which instructions in an algorithm are carried out.">flow of control</dfn> &mdash; which instruction comes next. You need to know five shapes:</p>

<table data-narration-id="n14">
  <thead><tr><th>Shape</th><th>Name</th><th>Used for</th></tr></thead>
  <tbody>
    <tr><td>Oval / rounded rectangle</td><td>Terminator</td><td>START and STOP of the algorithm</td></tr>
    <tr><td>Rectangle</td><td>Process</td><td>Any calculation, assignment or output step</td></tr>
    <tr><td>Parallelogram</td><td>Input / Output</td><td>Receiving data from the user or displaying a result</td></tr>
    <tr><td>Diamond</td><td>Decision</td><td>A yes/no question &mdash; branches the flow</td></tr>
    <tr><td>Rectangle with double side bars</td><td>Subroutine call</td><td>Calling a named subroutine or function</td></tr>
  </tbody>
</table>

<div class="key-fact" data-narration-id="n15" data-revision-tip="Close this and sketch the five flowchart shapes from memory. Label each one with its name and what it is used for.">
  <div class="key-fact-label">Key Fact</div>
  <p>Every flowchart must start and end with a terminator (oval). Decision diamonds always have exactly two exit arrows, typically labelled &ldquo;Yes&rdquo; and &ldquo;No&rdquo;. Process boxes have one entry and one exit arrow.</p>
</div>

<div class="collapsible">
  <button class="collapsible-toggle" aria-expanded="false">
    <span>Common Misconceptions About Pseudocode vs Code</span>
    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>
  </button>
  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n16">Many students write Python or JavaScript instead of pseudocode when the exam asks for an algorithm. While examiners usually award marks for logically correct code, there are two risks. First, Python&rsquo;s <code>print()</code> is not the same as <code>OUTPUT</code> &mdash; if your Python is wrong, you score zero. Second, pseudocode is faster to write in exam conditions because you don&rsquo;t worry about syntax errors.</p>
    <p data-narration-id="n17">Another common error is writing prose instead of pseudocode: &ldquo;Ask the user for a number, add it to the total, and repeat.&rdquo; This is not pseudocode &mdash; it has no control structure keywords and cannot be traced step by step. Always use the keywords: <code>RECEIVE</code>, <code>SET</code>, <code>FOR</code>, <code>WHILE</code>, <code>IF</code>.</p>
  </div></div>
</div>

<h2 data-narration-id="n18">Trace Tables</h2>
<p data-narration-id="n19">A trace table is used to check an algorithm by simulating it line by line. You create a column for every variable, plus an output column. Then you work through the algorithm and record the value of each variable after each step. Trace-table questions are a regular feature of the written exam &mdash; many students give only the final answer and lose intermediate marks.</p>

<div class="collapsible">
  <button class="collapsible-toggle" aria-expanded="false">
    <span>Worked Trace: Counting Loop</span>
    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>
  </button>
  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n20">Consider this algorithm:</p>
    <pre data-narration-id="n21"><code>SET total = 0
FOR i = 1 TO 3
  SET total = total + i
NEXT i
OUTPUT total</code></pre>
    <p data-narration-id="n22">Trace table:</p>
    <table>
      <thead><tr><th>Line</th><th>i</th><th>total</th><th>Output</th></tr></thead>
      <tbody>
        <tr><td>SET total = 0</td><td>&mdash;</td><td>0</td><td></td></tr>
        <tr><td>i = 1, total = 0 + 1</td><td>1</td><td>1</td><td></td></tr>
        <tr><td>i = 2, total = 1 + 2</td><td>2</td><td>3</td><td></td></tr>
        <tr><td>i = 3, total = 3 + 3</td><td>3</td><td>6</td><td></td></tr>
        <tr><td>OUTPUT total</td><td></td><td></td><td>6</td></tr>
      </tbody>
    </table>
    <p data-narration-id="n23">The answer is 6. Fill in every row &mdash; marks are awarded per row, not just for the final output.</p>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n25">Key Takeaways</h3>
<ul>
  <li data-narration-id="n26">An algorithm is a finite, unambiguous set of steps for solving a problem; pseudocode and flowcharts are two standard ways to express one before coding begins.</li>
  <li data-narration-id="n27">Pseudocode uses keywords such as SET, OUTPUT, RECEIVE, IF, FOR, WHILE, and REPEAT &mdash; learn the exact conventions used in your exam.</li>
  <li data-narration-id="n28">Flowchart shapes have fixed meanings: ovals are terminators, rectangles are processes, parallelograms are input/output, diamonds are decisions, and double-barred rectangles are subroutine calls.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n24">When a question asks you to &ldquo;write an algorithm in pseudocode&rdquo;, use the correct keywords: <code>SET</code>, <code>OUTPUT</code>, <code>RECEIVE</code>, <code>IF/ELSE/END IF</code>, <code>FOR/NEXT</code>, <code>WHILE/END WHILE</code>. Writing Python without being asked is risky &mdash; one syntax slip costs marks. For trace-table questions, complete <em>every row</em> &mdash; the mark scheme awards a mark for each correct intermediate state, not just the final output.</p>
