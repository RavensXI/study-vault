--- CONTENT_HTML ---
<h2 data-narration-id="n1">Why Sorting Matters</h2>
<p data-narration-id="n2">Sorting is one of the most studied problems in computer science. A sorted list unlocks binary search, makes data easier to present to users, and is a prerequisite for many other algorithms. Your exam covers two sorting algorithms: <dfn class="term" data-def="A sorting algorithm that repeatedly steps through a list, comparing adjacent items and swapping them if they are in the wrong order, until no swaps are needed.">bubble sort</dfn> and <dfn class="term" data-def="A sorting algorithm that uses divide-and-conquer: it splits the list in half repeatedly, sorts each half recursively, then merges the sorted halves back together.">merge sort</dfn>. You need to trace both by hand and compare their efficiency.</p>

<h2 data-narration-id="n3">Bubble Sort</h2>
<p data-narration-id="n4">Bubble sort gets its name because larger values &ldquo;bubble&rdquo; towards the end of the list with each pass. In each pass, the algorithm compares pairs of adjacent items and swaps them if they are in the wrong order. After each pass, the largest unsorted item is guaranteed to be in its correct position at the end.</p>
<p data-narration-id="n5">Here is bubble sort in pseudocode:</p>
<pre data-narration-id="n6"><code>SET n = LENGTH(list)
FOR pass = 1 TO n - 1
  FOR i = 0 TO n - pass - 1
    IF list[i] &gt; list[i + 1] THEN
      SET temp = list[i]
      SET list[i] = list[i + 1]
      SET list[i + 1] = temp
    END IF
  NEXT i
NEXT pass</code></pre>
<p data-narration-id="n7">Notice the three-variable swap using <code>temp</code>. This is the classic pattern: you cannot swap two values directly without a temporary variable, or one value overwrites the other before it is saved.</p>

<div class="key-fact" data-narration-id="n13" data-revision-tip="Cover this and write down bubble sort's worst-case complexity. Then explain why it is called O(n squared) using the number of comparisons in each pass.">
  <div class="key-fact-label">Key Fact</div>
  <p>Bubble sort has a worst-case time complexity of O(n<sup>2</sup>): for a list of <em>n</em> items, it may need up to approximately n<sup>2</sup> comparisons. This makes it slow for large lists. The best case is O(n) when the list is already sorted (one pass with no swaps confirms it is sorted).</p>
</div>

<h2 data-narration-id="n14">Merge Sort</h2>
<p data-narration-id="n15">Merge sort is a <dfn class="term" data-def="An algorithm design strategy that solves a problem by splitting it into smaller sub-problems, solving each, then combining the results.">divide-and-conquer</dfn> algorithm. It works in two distinct phases: first it splits the list into halves repeatedly until every sub-list has just one item, then it merges the sub-lists back together in sorted order. A single-item list is always sorted by definition, which is why splitting all the way down works.</p>

<div class="key-fact" data-narration-id="n25" data-revision-tip="Without looking, name the two phases of merge sort and explain what happens in each. Can you say the complexity in Big-O notation?">
  <div class="key-fact-label">Key Fact</div>
  <p>Merge sort has a worst-case time complexity of O(n log n). It splits the list in log n levels and does n comparisons per merge level. This is significantly more efficient than bubble sort&rsquo;s O(n<sup>2</sup>) for large datasets, which is why merge sort is used in many real-world applications.</p>
</div>

<h2 data-narration-id="n26">Comparing Bubble Sort and Merge Sort</h2>
<p data-narration-id="n27">In exam &ldquo;compare&rdquo; questions, do not just describe each algorithm separately &mdash; make explicit contrasts using &ldquo;unlike&rdquo; or &ldquo;whereas.&rdquo;</p>
<table data-narration-id="n28">
  <thead><tr><th>Feature</th><th>Bubble sort</th><th>Merge sort</th></tr></thead>
  <tbody>
    <tr><td>Worst-case complexity</td><td>O(n<sup>2</sup>)</td><td>O(n log n)</td></tr>
    <tr><td>Strategy</td><td>Repeatedly swap adjacent items</td><td>Divide and conquer: split then merge</td></tr>
    <tr><td>Memory use</td><td>In-place (little extra memory)</td><td>Needs extra memory for merged sub-lists</td></tr>
    <tr><td>Ease of implementation</td><td>Simple to write and understand</td><td>More complex, especially the merge step</td></tr>
    <tr><td>Performance on small lists</td><td>Acceptable</td><td>Overhead of splitting may not be worth it</td></tr>
    <tr><td>Performance on large lists</td><td>Very slow</td><td>Much faster</td></tr>
  </tbody>
</table>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n30">Key Takeaways</h3>
<ul>
  <li data-narration-id="n31">Bubble sort repeatedly swaps adjacent items in each pass; it is simple to implement but has worst-case O(n<sup>2</sup>) complexity, making it slow for large lists.</li>
  <li data-narration-id="n32">Merge sort splits the list into single items then merges them in sorted order; its O(n log n) complexity makes it much faster on large datasets, though it uses more memory.</li>
  <li data-narration-id="n33">For exam traces, show every intermediate state &mdash; one mark per correct row &mdash; and use explicit contrasting language when comparing the two algorithms.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n29">Trace-table questions on sorting are a regular mark sink. For bubble sort, show every comparison and swap within each pass &mdash; do not skip to the end of a pass. For merge sort, show both the split phase (all the way down to single items) and the merge phase (each comparison that produces a merged output). State the complexity of each algorithm &mdash; bubble sort: O(n<sup>2</sup>), merge sort: O(n log n) &mdash; and link complexity to list size when answering &ldquo;which sort is more suitable?&rdquo; questions.</p>
