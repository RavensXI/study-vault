--- DESCRIPTION ---
Integers, reals, Booleans, characters and strings, plus arrays and records for storing data.

--- CONTENT_HTML ---
<p data-narration-id="n1">Computers do not really know the difference between a person&rsquo;s age, a price in pounds, and the answer to a yes-or-no question &mdash; unless you tell them. A <dfn class="term" data-def="A category that tells the computer what kind of value is being stored and what can be done with it.">data type</dfn> is the label a program attaches to a piece of data so the computer knows how to store it and what it is allowed to do with it. Choosing types well is one of the marks of a careful programmer.</p>

<h3 data-narration-id="n2">The basic data types</h3>

<p data-narration-id="n3">A handful of types are used again and again. An <dfn class="term" data-def="A whole number with no fractional or decimal part, such as 42 or -7.">integer</dfn> is a whole number with nothing after a decimal point, so it suits counting things like lives, scores or the number of students in a class. A <dfn class="term" data-def="A number that includes a fractional or decimal part, such as 3.14 or 19.99; also called a float.">real</dfn> number, sometimes called a float, has a decimal part, which makes it right for measurements and money, such as a height of 1.72 metres or a price of &pound;19.99.</p>

<p data-narration-id="n4">A <dfn class="term" data-def="A data type that can hold only one of two values: True or False.">Boolean</dfn> can hold only one of two values, True or False. It is the natural choice for anything with a yes-or-no answer, such as whether a user is logged in or whether a game has been paused.</p>

<p data-narration-id="n5">The last two deal with text. A <dfn class="term" data-def="A single symbol such as a letter, digit, space or punctuation mark, for example the letter A.">character</dfn> is a single symbol &mdash; one letter, digit, space or punctuation mark. A <dfn class="term" data-def="A sequence of characters treated as one value, such as a word or a whole sentence.">string</dfn> is a sequence of characters joined together, so a name like &ldquo;Ada Lovelace&rdquo;, or even an empty piece of text, is a string. A string can contain digits, but if you store a phone number as a string you cannot do sums with it &mdash; it is text, not a number.</p>

<div class="key-fact" data-narration-id="n6" data-revision-tip="Cover this and write down the correct data type for each: a shoe size of 7, a price of 4.50, and whether a light is on.">
  <div class="key-fact-label">Key Fact</div>
  <p>The quickest way to tell an integer from a real is the decimal point. Whole numbers with no decimal part are integers; numbers that need a decimal part, including most prices and measurements, are reals.</p>
</div>

<h3 data-narration-id="n7">Casting: changing a value&rsquo;s type</h3>

<p data-narration-id="n8"><dfn class="term" data-def="Temporarily converting a value from one data type to another, for example turning the string 5 into the integer 5.">Casting</dfn> means temporarily converting a value from one type to another. Functions such as <code>int()</code> and <code>real()</code> turn text into numbers, while <code>str()</code> turns a number back into text. The original value does not change type for good; casting simply gives you the value in the form you need at that moment.</p>

<p data-narration-id="n9">Casting matters most when a program reads input. Whatever a user types at an <code>input</code> prompt arrives as a string, even when they type digits. To do arithmetic with it you must cast it first. So <code>age = int(input("How old are you? "))</code> reads the text and converts it into an integer the program can add to or compare.</p>

Casting each input with <code>int()</code> first makes the program store whole numbers, so 2 and 3 correctly give 5. This is one of the most common bugs a new programmer meets.</p>

<h3 data-narration-id="n11">Why the right data type matters</h3>

<p data-narration-id="n12">The type you choose decides three things. It decides which operations are allowed, because you can multiply two integers but not two Booleans. It affects how much memory is used, since a single character needs far less space than a long string. And it helps catch mistakes, because a program expecting an integer age can reject the text &ldquo;banana&rdquo; before it causes trouble later.</p>

<div class="key-fact" data-narration-id="n13" data-revision-tip="Close this and list the three reasons, given in the lesson, why choosing the correct data type is important.">
  <div class="key-fact-label">Key Fact</div>
  <p>Choosing a suitable data type is not just tidy &mdash; it controls which operations you can perform, how much memory the data uses, and whether invalid data can be spotted early.</p>
</div>

<h3 data-narration-id="n14">Data structures: arrays</h3>

<p data-narration-id="n15">Storing hundreds of values in separate variables would be a nightmare. An <dfn class="term" data-def="A data structure that stores many values of the same data type under one name, reached by an index number.">array</dfn> solves this by holding many values of the same data type under a single name. Each value is reached by its index, a position number that starts at 0, so the first item is at index 0, the second at index 1, and so on. Arrays have a fixed length, meaning their size is set when they are created and does not change.</p>

<pre data-narration-id="n16"><code>array colours[5]
colours[0] = "Blue"
colours[1] = "Pink"
print(colours[0])   // displays Blue</code></pre>

<p data-narration-id="n17">A one-dimensional (1D) array is a simple list. A two-dimensional (2D) array adds a second index so it behaves like a grid of rows and columns, which is ideal for a game board, a seating plan, or emulating the rows of a database table. You reach a cell with two numbers, one for the row and one for the column.</p>

<pre data-narration-id="n18"><code>array board[3,3]
board[0,0] = "X"
board[1,2] = "O"
print(board[1,2])   // displays O</code></pre>

<div class="collapsible">
  <button class="collapsible-toggle" aria-expanded="false">

  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n19">Suppose you need to store the marks of 30 students. Without an array you would need 30 separate variables and 30 lines just to add them up. With an array you can use a single loop that visits each index in turn, so the same few lines work whether there are 30 marks or 3000. This is why arrays and loops are so often used together.</p>
  </div></div>
</div>

<h3 data-narration-id="n20">Records</h3>

<p data-narration-id="n21">An array is perfect when every item is the same type, but real things often need several different pieces of information. A <dfn class="term" data-def="A data structure that groups together related fields about one thing, where the fields may be different data types.">record</dfn> groups related fields about one subject, and crucially those fields can be different data types. A single student record might hold a name as a string, an age as an integer, an average mark as a real, and whether fees are paid as a Boolean. You reach one field by its name, usually written with a dot.</p>

<pre data-narration-id="n22"><code>student.name = "Ada"      // string
student.age = 15          // integer
student.average = 72.4    // real
student.feesPaid = true   // Boolean
print(student.name)       // displays Ada</code></pre>

<div class="key-fact" data-narration-id="n23" data-revision-tip="Cover this and explain in one sentence how a record differs from an array.">
  <div class="key-fact-label">Key Fact</div>
  <p>The key difference is variety of type. An array holds many items of one single data type, whereas a record holds several fields about one thing and those fields can each be a different data type.</p>
</div>

<p data-narration-id="n24">Put these ideas together and you can model almost any information. You might use a record to describe one student and an array to hold a whole class of those records &mdash; the right data type inside the right data structure. Whenever you plan a program, ask what kind of value each item is, and whether you are storing one of something or many.</p>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n26">Key Takeaways</h3>
<ul>
  <li data-narration-id="n27">The basic data types are integer (whole numbers), real (decimals), Boolean (True or False), character (a single symbol) and string (text).</li>
  <li data-narration-id="n28">Casting temporarily converts a value from one type to another, which is essential because input always arrives as a string.</li>
  <li data-narration-id="n29">An array stores many values of the same type by index, while a record groups differently typed fields about one thing.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n25">Read the command word carefully. &lsquo;State&rsquo; or &lsquo;identify&rsquo; wants a short answer, such as naming a data type, while &lsquo;explain&rsquo; wants a reason or a worked example. A classic question gives a list of values and asks for the most suitable data type for each &mdash; remember that whole numbers are integers, anything with a decimal point is a real, True or False is Boolean, and text is a string. If a question involves reading input and then doing a calculation, mention casting, because that is exactly the skill being tested.</p>
