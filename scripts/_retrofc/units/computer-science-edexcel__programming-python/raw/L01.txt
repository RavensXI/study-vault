<h2 data-narration-id="n1">Why Data Types Matter</h2>
<p data-narration-id="n2">Every value stored in a Python program has a <dfn class="term" data-def="A classification that tells Python what kind of data is being stored, how much memory to allocate, and what operations are valid on it.">data type</dfn>. Choosing the right type is not optional &mdash; it determines what you can do with the data. You cannot multiply two strings together arithmetically. You cannot store the word &ldquo;open&rdquo; as a Boolean. Getting the type wrong causes errors that are often tricky to diagnose. Python works with five primitive data types you must know, plus structured types for grouping data together.</p>

<div class="key-fact" data-narration-id="n3" data-revision-tip="Cover this and list all five primitive data types with one example Python value for each.">
  <div class="key-fact-label">Key Fact</div>
  <p>The five primitive data types are: <strong>integer</strong> (whole number, e.g. <code>7</code> or <code>-3</code>), <strong>real</strong> (decimal number, e.g. <code>3.14</code> &mdash; Python calls this <code>float</code>), <strong>Boolean</strong> (<code>True</code> or <code>False</code>), <strong>char</strong> (a single character, e.g. <code>'A'</code>), and <strong>string</strong> (a sequence of characters, e.g. <code>&quot;hello&quot;</code>). In your exam, use the term <em>real</em> rather than <em>float</em> in written answers.</p>
</div>

<h2 data-narration-id="n4">The Primitive Data Types in Python</h2>
<p data-narration-id="n5">An <dfn class="term" data-def="A whole number with no decimal part, which can be positive, negative or zero.">integer</dfn> stores a whole number. Examples include a player&rsquo;s score, the number of students in a class, or a person&rsquo;s age. In Python, you write: <code>age = 16</code>.</p>
<p data-narration-id="n6">A <dfn class="term" data-def="A number that can include a decimal point; called 'float' in Python but referred to as 'real' in exam answers.">real</dfn> stores values with a fractional part. Examples include a temperature reading (<code>36.7</code>), a price (<code>12.99</code>), or a percentage (<code>78.5</code>). In Python: <code>temperature = 36.7</code>.</p>
<p data-narration-id="n7">A <dfn class="term" data-def="A data type that can hold only one of two values: True or False.">Boolean</dfn> holds only one of two values: <code>True</code> or <code>False</code>. Note the capital first letter &mdash; Python is case-sensitive. Examples: whether a user is logged in, whether a door sensor is triggered, whether a password matches.</p>
<p data-narration-id="n8">A <dfn class="term" data-def="A data type that holds exactly one character, such as a letter, digit or punctuation mark.">char</dfn> stores exactly one symbol. In Python, characters are written in single quotes: <code>'A'</code>, <code>'9'</code>, <code>'!'</code>. A <dfn class="term" data-def="A data type that holds a sequence of zero or more characters, used to store text such as names, messages and postcodes.">string</dfn> is a sequence of characters &mdash; as long or short as needed, including an empty string <code>&quot;&quot;</code>. In Python: <code>name = &quot;Priya&quot;</code>.</p>

  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n9">When a user types a number using <code>input()</code>, Python receives it as a <strong>string</strong> by default. Trying to add two such strings gives concatenation, not arithmetic. For example: <code>&quot;5&quot; + &quot;3&quot;</code> gives <code>&quot;53&quot;</code>, not <code>8</code>. You must convert the input before doing any maths:</p>
    <pre data-narration-id="n10">age = int(input(&quot;Enter your age: &quot;))
year_of_birth = 2026 - age
print(year_of_birth)</pre>
    <p data-narration-id="n11">Use <code>int()</code> for whole numbers and <code>float()</code> for decimals. This is one of the most common errors in exam answers &mdash; always check whether a variable storing user input has been converted to the right type.</p>

</div>

<h2 data-narration-id="n12">Variables and Constants</h2>
<p data-narration-id="n13">A <dfn class="term" data-def="A named storage location in memory whose value can change while the program runs.">variable</dfn> is a named location in memory whose value can change as the program executes. In Python, you create a variable simply by assigning a value to it: <code>score = 0</code>. Every variable has a <strong>name</strong> (its identifier), a <strong>value</strong>, and an implied data type.</p>
<p data-narration-id="n14">A <dfn class="term" data-def="A named value that is set once and must not change during program execution; conventionally written in uppercase to signal that it should not be altered.">constant</dfn> is a value that should stay fixed throughout the program. Python does not enforce constants with a keyword, but the convention is to write them in uppercase: <code>MAX_ATTEMPTS = 3</code>. Using a named constant makes maintenance far easier &mdash; if you later need to change the maximum to 5, you change it in one place rather than searching through every line of code for the number 3.</p>

<div class="key-fact" data-narration-id="n15" data-revision-tip="Test yourself: give one example of a poor identifier name and one good alternative for a variable storing the number of lives remaining in a game.">
  <div class="key-fact-label">Key Fact</div>
  <p>Meaningful <dfn class="term" data-def="The name given to a variable, constant or subprogram in a program; should clearly describe its purpose.">identifier</dfn> names make code readable and maintainable. <code>livesRemaining</code> is immediately clear; <code>x</code> or <code>temp</code> is not. Examiners award marks for meaningful identifiers when you write code &mdash; single-letter names (except conventional loop counters such as <code>i</code>) will cost marks.</p>
</div>

<h2 data-narration-id="n16">Structured Data Types</h2>
<p data-narration-id="n17">Beyond the five primitives, Python supports structured types that group multiple values together. An <dfn class="term" data-def="A structured data type that stores an ordered collection of values of the same type, accessed by position using an index.">array</dfn> (implemented in Python as a list) holds an ordered sequence of values. A <dfn class="term" data-def="A structured data type that groups related fields of different types together under one named structure, such as a student record holding a name, age and score.">record</dfn> groups related fields of potentially different types &mdash; implemented in Python using a dictionary. These are covered in detail in a later lesson.</p>

<h2 data-narration-id="n18">Writing Readable Code</h2>
<p data-narration-id="n19">The specification requires you to write code that is easy for another programmer to read. Four techniques contribute to readability: meaningful identifier names (already covered), correct <strong>indentation</strong>, useful <strong>comments</strong>, and consistent use of <strong>white space</strong>.</p>
<p data-narration-id="n20">In Python, <strong>indentation</strong> is not optional &mdash; it defines code blocks. All statements inside an <code>if</code>, <code>for</code> or function body must be indented by the same amount (usually four spaces). Inconsistent indentation causes an <code>IndentationError</code>.</p>

    <pre data-narration-id="n24"># Check whether a student has passed their exam
score = int(input(&quot;Enter exam score: &quot;))

if score &gt;= 50:
    print(&quot;Pass&quot;)
else:
    print(&quot;Fail&quot;)</pre>
    <p data-narration-id="n25">Notice: the comment explains the <em>purpose</em> of the block, not what each individual line does. Over-commenting &mdash; adding a comment to every single line &mdash; makes code harder to read, not easier. A common mistake in exam answers is writing more comment text than code.</p>

<h2 data-narration-id="n26">Initialisation and Assignment</h2>
<p data-narration-id="n27">Before you can use a variable, you must give it an initial value. This is called <strong>initialisation</strong>. For example, a score counter should start at zero: <code>score = 0</code>. Running total variables, list index counters and flag variables all need initialisation before a loop begins. Failing to initialise a variable causes a <code>NameError</code> in Python &mdash; the program tries to use a name it has never seen before.</p>

    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>

  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n28">When you encounter new code, try to <strong>predict</strong> its output before you run it. Consider:</p>
    <pre data-narration-id="n29">total = 0
for i in range(1, 5):
    total = total + i
print(total)</pre>
    <p data-narration-id="n30">Predict: <code>range(1, 5)</code> produces 1, 2, 3, 4. The loop adds each to <code>total</code>, giving 1, 3, 6, 10. The output is <code>10</code>. Then run it to verify. This predict-then-run habit is especially useful for tackling &ldquo;Complete a Trace Table&rdquo; questions in your exam.</p>
  </div></div>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n32">Key Takeaways</h3>
<ul>
  <li data-narration-id="n33">Python has five primitive data types: integer, real (float), Boolean, char and string. Use the term <em>real</em> in written exam answers.</li>
  <li data-narration-id="n34">Variables hold values that can change; constants (uppercase by convention) hold values that must not change. Both need meaningful identifier names.</li>
  <li data-narration-id="n35">Readable code uses meaningful identifiers, correct indentation, block-level comments (not per-line) and consistent white space.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n31">For &ldquo;Define&rdquo; questions on data types, be precise: a char holds <em>exactly one</em> character; a string holds <em>a sequence</em> of characters. Examiners penalise vague answers such as &ldquo;it holds text.&rdquo; For &ldquo;Identify&rdquo; questions about which data type to use, pick the most specific type &mdash; if a value is always a whole number, choose integer rather than real. For &ldquo;Write&rdquo; questions, always use meaningful identifier names and add one block-level comment &mdash; not a comment on every line.</p>
