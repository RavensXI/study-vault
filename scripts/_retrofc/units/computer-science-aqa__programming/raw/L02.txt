--- CONTENT_HTML ---
<h2 data-narration-id="n1">Iteration: Repeating Instructions</h2>
<p data-narration-id="n2"><dfn class="term" data-def="A programming construct that repeats a block of instructions, using either a fixed count or a condition to determine when to stop.">Iteration</dfn> allows a program to repeat a block of code without the programmer writing it out multiple times. There are two categories: <strong>definite iteration</strong>, where the number of repetitions is known in advance, and <strong>indefinite iteration</strong>, where the loop continues until a condition becomes true or false. You need a theoretical understanding of all four loop types, even if your school&rsquo;s chosen programming language does not support all of them.</p>

<h2 data-narration-id="n3">Definite Iteration &mdash; The FOR Loop</h2>
<p data-narration-id="n4"><dfn class="term" data-def="A count-controlled loop that repeats a fixed number of times, with the number of iterations determined before the loop begins.">Definite iteration</dfn> uses a <code>FOR</code> loop. The loop variable counts from a start value to an end value, incrementing by one on each pass. In AQA pseudo-code:</p>
<p data-narration-id="n5"><code>FOR i &larr; 1 TO 5<br/>&nbsp;&nbsp;OUTPUT i<br/>ENDFOR</code><br/>This outputs 1, 2, 3, 4, 5 &mdash; five iterations, one for each value of <code>i</code>.</p>
<p data-narration-id="n6">Use a FOR loop when you know exactly how many times the loop should run &mdash; for example, processing each of ten exam answers, or generating a times table from 1 to 12.</p>

<h2 data-narration-id="n7">Indefinite Iteration &mdash; Condition at the Start: WHILE</h2>
<p data-narration-id="n8"><dfn class="term" data-def="A condition-controlled loop that checks its condition before executing the loop body; if the condition is false from the start, the body may never execute.">Indefinite iteration</dfn> continues until a condition changes. The <code>WHILE</code> loop checks its condition <strong>before</strong> each iteration. If the condition is false when the loop is first reached, the body never executes at all.</p>
<p data-narration-id="n9"><code>WHILE password &ne; &ldquo;secret&rdquo;<br/>&nbsp;&nbsp;password &larr; USERINPUT<br/>ENDWHILE<br/>OUTPUT &ldquo;Access granted&rdquo;</code><br/>This keeps asking for input while the password is wrong. If the user gets it right on the first attempt, the loop body runs once; if they never get it right, it runs indefinitely.</p>

<h2 data-narration-id="n10">Indefinite Iteration &mdash; Condition at the End: REPEAT...UNTIL and DO...WHILE</h2>
<p data-narration-id="n11">Two loop forms check their condition <em>after</em> the body has run, which guarantees the body executes <strong>at least once</strong>.</p>
<p data-narration-id="n12"><strong>REPEAT&hellip;UNTIL</strong> continues the body until the condition becomes <em>true</em>:</p>
<p data-narration-id="n13"><code>REPEAT<br/>&nbsp;&nbsp;pin &larr; USERINPUT<br/>UNTIL pin = 1234<br/>OUTPUT &ldquo;PIN accepted&rdquo;</code><br/>The user is always asked for a PIN at least once, then again until they enter the correct value.</p>
<p data-narration-id="n14"><strong>DO&hellip;WHILE</strong> continues the body while the condition remains <em>true</em>:</p>
<p data-narration-id="n15"><code>DO<br/>&nbsp;&nbsp;answer &larr; USERINPUT<br/>WHILE answer &ne; &ldquo;quit&rdquo;</code><br/>This is logically identical to REPEAT&hellip;UNTIL except for whether the condition is expressed as &ldquo;stop when X&rdquo; or &ldquo;continue while X&rdquo;.</p>

<div class="key-fact" data-narration-id="n16" data-revision-tip="Cover this and recall: Which loop types check the condition before executing the body, and which check it after? Name all four loop types.">
  <div class="key-fact-label">Key Fact</div>
  <p>Condition checked <strong>before</strong> body: WHILE (may never execute). Condition checked <strong>after</strong> body: REPEAT&hellip;UNTIL and DO&hellip;WHILE (always execute at least once). Count-controlled: FOR (fixed number of iterations). All four are part of the specification even if Python (which lacks DO&hellip;WHILE and REPEAT&hellip;UNTIL natively) is your school&rsquo;s chosen language.</p>
</div>

<h2 data-narration-id="n20">Nested Iteration and Nested Selection</h2>
<p data-narration-id="n21">Loops and conditionals can be placed inside other loops and conditionals. This is called <dfn class="term" data-def="A programming structure where one loop or selection construct is placed inside another, creating multiple levels of control flow.">nesting</dfn>. Nested structures are used for grid operations, table printing, and multi-condition checks.</p>
<p data-narration-id="n22">A common exam mistake is incorrectly handling the boundary condition in a nested IF. For example:</p>
<p data-narration-id="n23"><code>IF score &gt;= 40 THEN<br/>&nbsp;&nbsp;OUTPUT &ldquo;Pass&rdquo;<br/>&nbsp;&nbsp;IF score &gt;= 70 THEN<br/>&nbsp;&nbsp;&nbsp;&nbsp;OUTPUT &ldquo;Merit&rdquo;<br/>&nbsp;&nbsp;ENDIF<br/>ENDIF</code><br/>Students often accidentally output &ldquo;Merit&rdquo; without checking that the outer IF&rsquo;s condition was also met first. Always trace through nested conditions carefully.</p>

  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n24"><strong>Arithmetic operators:</strong> <code>+</code> (add), <code>&minus;</code> (subtract), <code>&times;</code> (multiply), <code>/</code> (real division &mdash; result can be decimal), <code>DIV</code> (integer division &mdash; whole quotient only), <code>MOD</code> (remainder after integer division).</p>
    <p data-narration-id="n25"><strong>Relational operators</strong> (for comparisons in conditions): <code>=</code> (equal to), <code>&ne;</code> (not equal to), <code>&lt;</code> (less than), <code>&gt;</code> (greater than), <code>&le;</code> (less than or equal to), <code>&ge;</code> (greater than or equal to). These return a Boolean result (true or false).</p>
    <p data-narration-id="n26"><strong>Boolean operators</strong> combine conditions: <code>AND</code> (both conditions must be true), <code>OR</code> (at least one must be true), <code>NOT</code> (inverts a condition). Example: <code>IF age &ge; 16 AND hasConsent = TRUE THEN</code> &mdash; both conditions must hold.</p>
  </div></div>
</div>

<div class="key-fact" data-narration-id="n27" data-revision-tip="Test yourself: Write a condition using AND that checks whether a number stored in 'n' is greater than 0 and less than 100.">
  <div class="key-fact-label">Key Fact</div>
  <p>Boolean operators are used to combine multiple conditions in a single IF or WHILE statement. <strong>AND</strong> requires all combined conditions to be true. <strong>OR</strong> requires at least one to be true. <strong>NOT</strong> inverts a Boolean value: <code>NOT gameOver</code> is true when <code>gameOver</code> is false.</p>
</div>

<h2 data-narration-id="n28">Putting It Together &mdash; A Real Example</h2>
<p data-narration-id="n29">Consider a simple number-guessing game. The target number is 42. The player keeps guessing until they get it right or run out of attempts. This combines a WHILE loop (indefinite, condition at start), selection (IF to check the guess), Boolean operators, and counter variables:</p>
<p data-narration-id="n30"><code>target &larr; 42<br/>attempts &larr; 0<br/>maxAttempts &larr; 5<br/>guess &larr; 0<br/>WHILE guess &ne; target AND attempts &lt; maxAttempts<br/>&nbsp;&nbsp;guess &larr; USERINPUT<br/>&nbsp;&nbsp;attempts &larr; attempts + 1<br/>ENDWHILE<br/>IF guess = target THEN<br/>&nbsp;&nbsp;OUTPUT &ldquo;Correct!&rdquo;<br/>ELSE<br/>&nbsp;&nbsp;OUTPUT &ldquo;Out of attempts&rdquo;<br/>ENDIF</code></p>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n32">Key Takeaways</h3>
<ul>
  <li data-narration-id="n33">Definite iteration (FOR) uses a fixed count. Indefinite iteration (WHILE, REPEAT&hellip;UNTIL, DO&hellip;WHILE) uses a condition. WHILE checks before; REPEAT&hellip;UNTIL and DO&hellip;WHILE check after &mdash; guaranteeing at least one execution.</li>
  <li data-narration-id="n34">Nesting places loops or selections inside each other. Trace nested conditions carefully &mdash; boundary errors in nested IFs are the most common exam mistake in this topic.</li>
  <li data-narration-id="n35">Arithmetic operators (+, &minus;, &times;, /, DIV, MOD), relational operators (=, &ne;, &lt;, &gt;, &le;, &ge;) and Boolean operators (AND, OR, NOT) are all used to build conditions and perform calculations in programs.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n31">For questions about iteration, always state which loop type you are using and why &mdash; examiners want to see that you have made a deliberate choice, not just used a FOR loop by default. If a question specifies pseudo-code, use AQA syntax with the correct closing keywords (ENDFOR, ENDWHILE, UNTIL). Remember: REPEAT&hellip;UNTIL and DO&hellip;WHILE always run at least once; WHILE may not run at all. For nested selection questions, trace through every branch carefully &mdash; missing the inner ENDIF is a very common error.</p>
