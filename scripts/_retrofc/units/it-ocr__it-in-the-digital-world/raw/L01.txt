Flow charts, mind maps, visualisation diagrams and wireframes — the design tools used to plan IT products.

--- CONTENT_HTML ---
<h2 data-narration-id="n1">Why Plan Before You Build?</h2>
<p data-narration-id="n2">Every successful IT product starts with a plan. Jumping straight into building a website, app or database without a design document wastes time and leads to costly mistakes. <dfn class="term" data-def="Documents created before building an IT solution to plan its structure, content and appearance.">Design tools</dfn> help developers, designers and clients agree on what the finished product should look like and how it should work &mdash; before a single line of code is written.</p>
<p data-narration-id="n3">The exam requires you to know four main types of design tool: flow charts, mind maps, visualisation diagrams and wireframes. For each one you must be able to describe its components, name software that creates it, and weigh up its advantages and disadvantages.</p>

<div class="key-fact" data-narration-id="n4" data-revision-tip="Cover this and recall: name all four design tools and write one component each uses that is different from the others.">
  <div class="key-fact-label">Key Fact</div>
  <p>The four design tools are flow charts, mind maps, visualisation diagrams and wireframes. Each suits a different planning purpose &mdash; process logic, brainstorming, appearance, and page layout respectively.</p>
</div>

<h2 data-narration-id="n5">Flow Charts</h2>
<p data-narration-id="n6">A <dfn class="term" data-def="A diagram that uses standard shapes and arrows to show the steps and decisions in a process.">flow chart</dfn> maps out a process step by step. It uses internationally recognised symbols: ovals (start/end), rectangles (process steps), diamonds (decisions with yes/no branches) and parallelograms (input/output). Arrows show the direction of flow.</p>
<p data-narration-id="n7">Flow charts are ideal when you need to show logic &mdash; for example, how a login system checks a username and password before granting access. Software such as Microsoft Visio, Lucidchart and even PowerPoint can create them, or they can be hand-sketched.</p>

    <p data-narration-id="n9"><strong>Disadvantages:</strong> can become very large and complex for multi-step systems; symbols must be used correctly or the diagram is misleading; updating a hand-drawn chart is time-consuming when the design changes.</p>

<h2 data-narration-id="n10">Mind Maps</h2>
<p data-narration-id="n11">A <dfn class="term" data-def="A branching diagram that places a central idea in the middle and radiates related topics, subtopics and details outwards.">mind map</dfn> is a brainstorming tool. A central idea sits in the middle, with branches radiating outwards to related topics, and sub-branches adding more detail. The spec identifies three specific types used in IT design projects.</p>
<p data-narration-id="n12">A <strong>library mind map</strong> organises a collection of resources or assets &mdash; for example, mapping all the images, audio clips and text files needed for a website. A <strong>tunnel timeline mind map</strong> sequences tasks over time, showing what must happen before the next stage can begin. A <strong>presentation mind map</strong> structures the content and flow of a presentation or report.</p>
<p data-narration-id="n13">Mind maps can be drawn by hand or created using software such as MindMeister, Coggle or Microsoft Word&rsquo;s SmartArt feature. They are quick to produce and easy to update as ideas evolve.</p>

<div class="collapsible">
  <button class="collapsible-toggle" aria-expanded="false">
    <span>Visualisation Diagrams and Wireframes</span>
    <svg class="collapsible-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><polyline points="6 9 12 15 18 9"/></svg>
  </button>
  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n14">A <dfn class="term" data-def="A design tool that shows what a finished IT product will look like, including colours, images, fonts and layout, but without working functionality.">visualisation diagram</dfn> (sometimes called a mock-up) shows the intended appearance of an IT product. It includes colours, images, fonts and the general layout &mdash; it looks like the real thing but is not interactive. It is useful for getting client sign-off on aesthetics before development starts.</p>
    <p data-narration-id="n15">A <dfn class="term" data-def="A basic structural plan of a web page or screen that shows the position of elements such as navigation menus, content areas and buttons, without colour or detailed design.">wireframe</dfn> is a skeletal layout of a single screen or web page. It uses simple boxes, placeholder text and labels to show where navigation menus, images, headings, forms and buttons will sit &mdash; but it deliberately avoids colour or imagery so the focus stays on structure and usability. Wireframes are often the first design step because they are quick to produce and cheap to revise.</p>
    <p data-narration-id="n16">Both can be created by hand or using specialist software. Tools widely used in schools and the workplace include Balsamiq (wireframes), Figma (visualisation diagrams) and PowerPoint or Google Slides (both).</p>
  </div></div>
</div>

<div class="key-fact" data-narration-id="n17" data-revision-tip="Close this and list: which design tool uses ovals, rectangles, diamonds and parallelograms as its standard components?">
  <div class="key-fact-label">Key Fact</div>
  <p>A flow chart uses four standard shapes: ovals (start/end), rectangles (process), diamonds (decision) and parallelograms (input/output). Using these symbols correctly is essential &mdash; the examiner rewards labelled, accurate designs.</p>
</div>

<h2 data-narration-id="n18">Sketches vs Software</h2>
<p data-narration-id="n19">Design tools can be created either by hand (sketching on paper) or using software. Each approach has its place. Hand sketches are fast, require no technology, and are ideal for early-stage brainstorming when ideas are still forming. They are also exactly what the exam&rsquo;s 8-mark &ldquo;create&rdquo; question requires &mdash; students hand-draw their design solution.</p>
<p data-narration-id="n20">Software-created designs look more professional, are easier to share with clients and team members, and are much simpler to edit when changes are needed. The trade-off is that software takes longer to learn and requires access to the correct application. In a professional project, hand sketches are typically used first and then refined digitally.</p>

<h2 data-narration-id="n21">Assessing Suitability</h2>
<p data-narration-id="n22">Choosing the right design tool for a given context is a key exam skill. Ask yourself: does the project need to show a <em>process or logic</em> (flow chart), explore <em>ideas or assets</em> (mind map), communicate <em>intended appearance</em> (visualisation diagram) or plan <em>page structure</em> (wireframe)? A scenario question might describe a developer building a new booking system &mdash; a flow chart suits the booking logic, a wireframe suits the booking form layout, and a visualisation diagram suits the client sign-off on colours and branding.</p>

<h3 data-narration-id="n24">Key Takeaways</h3>
<ul>
  <li data-narration-id="n25">The four design tools are flow charts (showing logic/process), mind maps (brainstorming/organising &mdash; three types: library, tunnel timeline, presentation), visualisation diagrams (showing appearance) and wireframes (showing page structure).</li>
  <li data-narration-id="n26">Design tools can be created by hand or using software; hand sketches are faster and used in the exam, software versions are more professional and easier to share or update.</li>
  <li data-narration-id="n27">Matching the right tool to the right context is a key exam skill &mdash; process logic needs a flow chart, page layout needs a wireframe, client aesthetics need a visualisation diagram.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n23">For the 8-mark &ldquo;create&rdquo; question you will be asked to hand-sketch a design tool for a given scenario &mdash; often a mind map, flow chart or wireframe. The biggest mark losses come from missing labels and diagrams that ignore the scenario. Use all four standard flow chart symbols if you draw a flow chart, label every branch of a mind map, and annotate every section of a wireframe. Examiners reward completeness, correct use of symbols and a clear link back to the named scenario &mdash; not artistic quality.</p>
