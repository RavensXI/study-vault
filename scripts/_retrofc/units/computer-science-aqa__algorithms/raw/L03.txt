<h2 data-narration-id="n1">Why Search Algorithms Matter</h2>
<p data-narration-id="n2">Searching is one of the most common operations in computing. Every time you look up a contact on your phone, find a product on a retail site, or ask a search engine a question, a <dfn class="term" data-def="A step-by-step process for locating a specific item within a collection of data.">search algorithm</dfn> is at work. The specification requires you to know two: linear search and binary search. Crucially, you must be able to compare them &mdash; choosing the right algorithm for a given situation is a practical engineering skill.</p>

<h2 data-narration-id="n3">Linear Search</h2>
<p data-narration-id="n4"><dfn class="term" data-def="A search algorithm that checks each item in a list one by one, starting from the first, until the target item is found or the end of the list is reached.">Linear search</dfn> is the simplest approach. Starting at the beginning of the list, it checks each item in turn: does this match the target? If yes, return its position. If no, move to the next item. If the end of the list is reached without a match, the target is not present.</p>
<p data-narration-id="n5">Linear search works on <strong>any</strong> list &mdash; sorted or unsorted. This makes it very flexible. You do not need to sort the data first, which saves time when you only need to search once.</p>

<div class="key-fact" data-narration-id="n6" data-revision-tip="Cover this and recall: two advantages and two disadvantages of linear search.">
  <div class="key-fact-label">Key Fact</div>
  <p><strong>Advantages of linear search:</strong> Simple to understand and implement. Works on unsorted data. <strong>Disadvantages:</strong> Slow for large datasets &mdash; in the worst case, every item must be checked. For a list of one million items, up to one million comparisons may be needed.</p>
</div>

<h2 data-narration-id="n7">Binary Search</h2>
<p data-narration-id="n8"><dfn class="term" data-def="A search algorithm that works only on sorted data by repeatedly halving the search area, comparing the target with the middle item and discarding the half that cannot contain it.">Binary search</dfn> is far more efficient than linear search, but it has one important requirement: <strong>the data must already be sorted</strong>. Binary search works by repeatedly halving the search area.</p>
<p data-narration-id="n9"><strong>The mechanics:</strong> Find the middle item of the current search area. If it equals the target, the search is done. If the target is smaller, discard the right half and repeat on the left. If the target is larger, discard the left half and repeat on the right. Continue until found or the search area is empty.</p>

<div class="key-fact" data-narration-id="n15" data-revision-tip="Test yourself: Explain in your own words why binary search is faster than linear search, and state its one essential requirement.">
  <div class="key-fact-label">Key Fact</div>
  <p>Binary search halves the search area with every comparison. A sorted list of 1,000 items needs at most 10 comparisons with binary search, versus up to 1,000 with linear search. A list of one million items needs at most 20 comparisons. <strong>The data must be sorted first &mdash; binary search cannot work on unsorted data.</strong></p>
</div>

<h2 data-narration-id="n16">Comparing the Two Algorithms</h2>
<p data-narration-id="n17">The spec requires you to compare and contrast these algorithms in terms of <strong>time efficiency</strong>. Note that formal analysis (such as Big O notation) is not required &mdash; you only need to explain which is faster and why, in plain English.</p>

      <li data-narration-id="n20">Simple to implement</li>
      <li data-narration-id="n21">Slow for large lists &mdash; checks items one by one</li>
      <li data-narration-id="n22">Best choice for small lists or lists that change frequently (re-sorting would cost more than a linear scan)</li>
    </ul>
    <p data-narration-id="n23"><strong>Binary search:</strong></p>
    <ul>
      <li data-narration-id="n24">Requires sorted data</li>
      <li data-narration-id="n25">More complex to implement</li>
      <li data-narration-id="n26">Very fast for large lists &mdash; halves the search area each step</li>
      <li data-narration-id="n27">Best choice for large, stable (rarely changing) sorted datasets where fast repeated searches are needed</li>
    </ul>

<h2 data-narration-id="n28">Choosing the Right Algorithm</h2>
<p data-narration-id="n29">If someone asks &ldquo;which algorithm is better?&rdquo;, the honest answer is: it depends. A phonebook app with 80 million entries benefits enormously from binary search &mdash; but the phonebook is kept in alphabetical order precisely to enable this. A small list of five items that changes every second is better served by linear search. Understanding this trade-off is what separates a competent programmer from someone who just follows a textbook.</p>

<div class="key-fact" data-narration-id="n30" data-revision-tip="Cover this and state two situations where linear search is the better choice, and two where binary search is preferred.">
  <div class="key-fact-label">Key Fact</div>
  <p>Use <strong>linear search</strong> when: the list is small (the efficiency advantage of binary search is negligible), the data is unsorted and sorting it would cost more time than a single scan, or the list changes so frequently that maintaining a sorted order is impractical. Use <strong>binary search</strong> when: the dataset is large, the data is already sorted or is sorted once and searched many times, and fast repeated look-ups are a priority. In real systems, databases maintain sorted indexes precisely so that binary-style search can be used at speed.</p>
</div>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n31">Key Takeaways</h3>
<ul>
  <li data-narration-id="n32">Linear search checks every item one by one; it works on any list but is slow for large datasets.</li>
  <li data-narration-id="n33">Binary search repeatedly halves the search area; it is far faster but requires the data to be sorted first.</li>
  <li data-narration-id="n34">Choosing between them depends on the size of the dataset, whether it is sorted, and how often it changes.</li>
</ul>
