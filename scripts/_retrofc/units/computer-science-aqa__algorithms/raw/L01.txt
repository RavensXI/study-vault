<h2 data-narration-id="n1">What Is Computational Thinking?</h2>
<p data-narration-id="n2"><dfn class="term" data-def="A problem-solving approach that involves breaking down complex problems, removing unnecessary detail, and designing step-by-step solutions so they can be carried out by a computer or human systematically.">Computational thinking</dfn> is a structured way of approaching problems so they can be solved clearly and efficiently. It is not about using a computer &mdash; it is about <em>thinking</em> in a way that makes complex problems manageable. Two key techniques are <strong>decomposition</strong> and <strong>abstraction</strong>. Together, they form the foundation of everything you will study in GCSE Computer Science.</p>

<div class="key-fact" data-narration-id="n3" data-revision-tip="Cover this and recall: What is the precise definition of an algorithm, and how does it differ from a computer program?">
  <div class="key-fact-label">Key Fact</div>
  <p>An <strong>algorithm</strong> is a <em>sequence</em> of steps that can be followed to complete a task. A computer program is an <em>implementation</em> of an algorithm in a specific programming language. The algorithm is the abstract plan; the program is the working code.</p>
</div>

<h2 data-narration-id="n4">Algorithms: Sequence Matters</h2>
<p data-narration-id="n5">The word &ldquo;sequence&rdquo; is deliberate. An algorithm is not simply a &ldquo;set&rdquo; of instructions &mdash; a set has no order. An algorithm&rsquo;s steps must be followed in the right order to reach the correct result. A recipe is an everyday example: if you add the eggs before the flour, you do not get the same result.</p>
<p data-narration-id="n6">Every algorithm can be expressed in different forms: as <dfn class="term" data-def="A way of writing an algorithm using structured, English-like statements that are not tied to any specific programming language.">pseudo-code</dfn>, as a flowchart, or as actual program code. You need to be comfortable moving between all three representations.</p>

<h2 data-narration-id="n7">Decomposition</h2>
<p data-narration-id="n8"><dfn class="term" data-def="Breaking a complex problem down into a number of smaller sub-problems, each of which accomplishes an identifiable task that can be solved more easily on its own.">Decomposition</dfn> means breaking a large, complex problem into smaller, more manageable sub-problems. Each sub-problem accomplishes a specific, identifiable task. Sub-problems can themselves be further broken down, creating a hierarchy of manageable tasks.</p>
<p data-narration-id="n9">Consider building a mobile banking app. At the top level it is one enormous problem. Decomposed, it becomes: user authentication, account balance display, payment processing, transaction history, and security alerts. Each of those can be decomposed further &mdash; payment processing breaks into input validation, fraud checks, bank transfer protocols, and confirmation messages. Each piece is now small enough for a developer (or a team) to tackle independently.</p>

<h2 data-narration-id="n16">Abstraction</h2>
<p data-narration-id="n17"><dfn class="term" data-def="The process of removing unnecessary detail from a problem, keeping only the information that is relevant to solving it.">Abstraction</dfn> means removing unnecessary detail so that you can focus on the information that actually matters. It is not about making things simpler than they are &mdash; it is about identifying which details are relevant and filtering out everything else.</p>
<p data-narration-id="n18">The London Underground map is a classic example. Real tube lines curve, dip underground, and vary in spacing. A geographically accurate map would be too cluttered to use. The Underground map abstracts away distances and precise geography, keeping only the connections between stations and their order. That is all a passenger needs to plan a journey.</p>

<div class="key-fact" data-narration-id="n19" data-revision-tip="Test yourself: Give one everyday example of abstraction and explain what detail has been removed and why.">
  <div class="key-fact-label">Key Fact</div>
  <p>In programming, abstraction happens constantly. A variable named <code>playerScore</code> hides the actual memory address where the value is stored. A function called <code>sendNotification()</code> hides dozens of lines of networking code behind a single meaningful name. Programmers use abstraction to manage complexity at every scale.</p>
</div>

<h2 data-narration-id="n20">Levels of Abstraction</h2>
<p data-narration-id="n21">Abstraction works at multiple levels. A sat-nav system abstracts away the physics of road surfaces, the full text of the Highway Code, and the mechanical workings of your car. It retains only: current position, destination, road network connections, and estimated speeds. The less detail the system has to process, the faster and clearer the route calculation.</p>
<p data-narration-id="n22">Similarly, when you design an algorithm you make abstraction decisions: what are the <strong>inputs</strong>? What <strong>processing</strong> happens on them? What are the <strong>outputs</strong>? Everything else &mdash; the hardware it runs on, the user interface colour scheme &mdash; is abstracted away from the algorithm itself.</p>

  <div class="collapsible-content"><div class="collapsible-inner">
    <p data-narration-id="n23">A school login system can be decomposed and abstracted as follows:</p>
    <p data-narration-id="n24"><strong>Decomposition:</strong> (1) Get username and password. (2) Check against stored records. (3) Either grant access or display an error.</p>
    <p data-narration-id="n25"><strong>Abstraction applied:</strong> The algorithm does not need to know how passwords are stored in the database, what operating system the server runs, or how the network packet gets from the student&rsquo;s laptop to the server. It only needs: <em>username</em>, <em>password</em>, <em>stored credentials</em>, and a <em>match/no-match decision</em>.</p>
    <p data-narration-id="n26"><strong>Inputs:</strong> username, password. <strong>Processing:</strong> compare input to stored values. <strong>Output:</strong> &ldquo;Access granted&rdquo; or &ldquo;Access denied.&rdquo;</p>
  </div></div>
</div>

<h2 data-narration-id="n27">Why These Skills Matter</h2>
<p data-narration-id="n28">Decomposition and abstraction are not just theory &mdash; they are the practical habits of every professional software developer. When engineers at a social media company build a new feature for hundreds of millions of users, they start by decomposing the requirement into sub-tasks and abstracting away the hardware and infrastructure concerns. The same thinking applies when you write even a short program in school.</p>
<p data-narration-id="n29">In your exam, you may be asked to explain what decomposition or abstraction means, apply them to a given scenario, or identify where they appear in a described system. Always ground your answer in the specific problem given &mdash; examiners reward precise application, not generic definitions.</p>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n31">Key Takeaways</h3>
<ul>
  <li data-narration-id="n32">An algorithm is a <em>sequence</em> of steps to complete a task. A computer program is one implementation of an algorithm &mdash; the two are not the same thing.</li>
  <li data-narration-id="n33">Decomposition means breaking a problem into sub-problems, each accomplishing an identifiable task that can be solved more easily on its own.</li>
  <li data-narration-id="n34">Abstraction means removing unnecessary detail from a problem, keeping only the inputs, processing and outputs the algorithm needs to function.</li>
</ul>
