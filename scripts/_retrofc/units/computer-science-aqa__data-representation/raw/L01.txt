--- CONTENT_HTML ---
<h2 data-narration-id="n1">Why Computers Use Binary</h2>
<p data-narration-id="n2">Every piece of data inside a computer &mdash; text, images, sound, instructions &mdash; is ultimately stored and processed as a pattern of 1s and 0s. This is the <dfn class="term" data-def="A number system that uses only two digits, 0 and 1. Every circuit in a computer is either on (1) or off (0), making binary the natural language of digital hardware.">binary</dfn> (base-2) number system. A transistor in a chip is either conducting electricity or not &mdash; that two-state physical reality maps perfectly onto binary&rsquo;s two digits. Every other number system we use in computing is ultimately a convenient way of writing or working with binary data.</p>

<h2 data-narration-id="n3">Place Values in Binary</h2>
<p data-narration-id="n4">Just as <dfn class="term" data-def="The standard base-10 number system we use every day, using digits 0&ndash;9.">denary</dfn> (decimal, base-10) uses place values of 1, 10, 100, 1000&hellip;, binary uses place values that are powers of 2. For an 8-bit number, the place values from left (most significant) to right (least significant) are:</p>
<p data-narration-id="n5"><strong>128 &mdash; 64 &mdash; 32 &mdash; 16 &mdash; 8 &mdash; 4 &mdash; 2 &mdash; 1</strong></p>
<p data-narration-id="n6">The maximum 8-bit value is 11111111, which equals 128+64+32+16+8+4+2+1 = <strong>255</strong>. An 8-bit binary number can therefore represent any whole number from 0 to 255.</p>

<div class="key-fact" data-narration-id="n7" data-revision-tip="Cover this and write out the 8 place values from memory, then use them to convert 10110100 to denary.">
  <div class="key-fact-label">Key Fact</div>
  <p>An 8-bit binary number has place values <strong>128, 64, 32, 16, 8, 4, 2, 1</strong> (left to right). To convert binary to denary, add up the place values where the digit is 1. The maximum 8-bit value is 11111111 = 255. Decimal values from 0 to 255 must be representable.</p>
</div>

<h2 data-narration-id="n11">Hexadecimal</h2>
<p data-narration-id="n12"><dfn class="term" data-def="A base-16 number system using digits 0&ndash;9 and letters A&ndash;F. Each hex digit represents exactly four binary bits (one nibble).">Hexadecimal</dfn> (hex, base-16) uses 16 symbols: digits 0&ndash;9 and letters A&ndash;F, where A = 10, B = 11, C = 12, D = 13, E = 14, F = 15. The maximum 8-bit value in hex is <strong>FF</strong> (both nibbles at maximum). Hex is widely used because it is a compact shorthand for binary: every four bits (one <dfn class="term" data-def="A group of 4 bits. One nibble converts directly to one hexadecimal digit.">nibble</dfn>) maps to exactly one hex digit, making long binary strings much easier for humans to read.</p>
<p data-narration-id="n13">You will see hex everywhere: web colour codes (#FF5500), MAC addresses on network cards, memory dump listings in diagnostic tools. Computers do not process hex directly &mdash; it is a human convenience for representing binary concisely.</p>

    Split into nibbles: 1100 | 1010<br>
    1100 = 12 = C<br>
    1010 = 10 = A<br>
    <strong>Result: CA</strong></p>
    <p data-narration-id="n15"><strong>Hex &rarr; Denary:</strong> Convert CA<br>
    C = 12; A = 10<br>
    (12 &times; 16) + 10 = 192 + 10 = <strong>202</strong></p>
    <p data-narration-id="n16"><strong>Denary &rarr; Hex:</strong> Convert 200<br>
    200 &divide; 16 = 12 remainder 8<br>
    12 = C, 8 = 8<br>
    <strong>Result: C8</strong><br>
    Check: (12 &times; 16) + 8 = 192 + 8 = 200 &#10003;</p>
  </div></div>
</div>

<div class="key-fact" data-narration-id="n17" data-revision-tip="Test yourself: convert 10110011 to hex without notes. Split into nibbles, convert each, write the two hex digits.">
  <div class="key-fact-label">Key Fact</div>
  <p>To convert binary to hex: split into groups of 4 bits (nibbles) from the right, then convert each nibble to its hex digit. The maximum 8-bit value is <strong>FF</strong> in hex, <strong>255</strong> in denary. To convert hex to denary: multiply the first digit by 16 and add the second.</p>
</div>

<h2 data-narration-id="n18">Units of Information</h2>
<p data-narration-id="n19">A single binary digit is called a <dfn class="term" data-def="The smallest unit of data in a computer, representing a single binary digit: either 0 or 1.">bit</dfn>. Eight bits together form a <dfn class="term" data-def="A group of 8 bits. The standard unit for measuring data storage.">byte</dfn>. The convention on this course uses the SI decimal prefixes &mdash; not powers of 2:</p>
<ul>
  <li data-narration-id="n20"><strong>kilobyte (kB)</strong> = 1,000 bytes</li>
  <li data-narration-id="n21"><strong>megabyte (MB)</strong> = 1,000 kilobytes</li>
  <li data-narration-id="n22"><strong>gigabyte (GB)</strong> = 1,000 megabytes</li>
  <li data-narration-id="n23"><strong>terabyte (TB)</strong> = 1,000 gigabytes</li>
</ul>
<p data-narration-id="n24">Note: you may have seen the prefix &ldquo;kibi&rdquo; (KiB = 1,024 bytes) used in some contexts, but this course uses the decimal SI convention only. Do not write 1 kB = 1,024 bytes in your exam answers.</p>

<h2 data-narration-id="n25">Binary Addition</h2>
<p data-narration-id="n26">Binary addition follows four simple rules: 0+0=0; 1+0=1; 1+1=0 carry 1; 1+1+1=1 carry 1. The exam will ask you to add up to <strong>three</strong> 8-bit numbers in a single column, meaning the maximum number of 1s in any column is three. Answers stay within 8 bits &mdash; exam questions will not require carrying beyond the eighth bit.</p>

<h2 data-narration-id="n30">Binary Shifts</h2>
<p data-narration-id="n31">A <dfn class="term" data-def="Moving all bits in a binary number left or right by a set number of positions. A left shift multiplies the number by a power of 2; a right shift divides it.">binary shift</dfn> moves every bit in a number left or right by a stated number of positions. Bits that move beyond the 8-bit boundary are lost. Empty positions are filled with 0.</p>
<p data-narration-id="n32">A <strong>left shift by 1</strong> multiplies the value by 2. A <strong>left shift by 2</strong> multiplies by 4. A <strong>right shift by 1</strong> divides by 2 (integer division &mdash; any remainder is lost). A <strong>right shift by 2</strong> divides by 4.</p>
<p data-narration-id="n33">Example: 00001100 (12) left-shifted by 2 &rarr; 00110000 = 48. Check: 12 &times; 4 = 48. Right-shifted by 1 &rarr; 00000110 = 6. Check: 12 &divide; 2 = 6. Binary shifts are used in image processing, audio signal scaling, and efficient arithmetic in embedded systems where multiplying by a power of 2 is extremely common.</p>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n35">Key Takeaways</h3>
<ul>
  <li data-narration-id="n36">Binary (base-2) uses place values 128, 64, 32, 16, 8, 4, 2, 1 for 8-bit numbers (0&ndash;255). Hex (base-16) is a compact shorthand: each nibble (4 bits) maps to one hex digit, giving a maximum of FF for 8 bits.</li>
  <li data-narration-id="n37">Binary addition: 1+1=0 carry 1; 1+1+1=1 carry 1. Left shifts multiply by powers of 2; right shifts divide. Exam questions use a maximum of 8 bits with no carry beyond bit 8.</li>
  <li data-narration-id="n38">Data units use decimal SI prefixes: 1 kB = 1,000 bytes, 1 MB = 1,000 kB, 1 GB = 1,000 MB, 1 TB = 1,000 GB.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n34">For &ldquo;3 marks &mdash; Convert (Number Base)&rdquo; questions, always show your working: write out the place values, label which are 1 and which are 0, and state the final answer in the requested base. Stripping leading zeros from a binary answer (e.g. writing 1101 when the question asks for 8 bits) costs marks &mdash; always pad to the requested bit length. If converting via hex, split into nibbles and convert each separately. Watch out for the units question: on this course 1 kB = 1,000 bytes, not 1,024.</p>
