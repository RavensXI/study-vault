Bitmap pixels, colour depth, image file size, sound sampling rate and calculating audio file sizes.

--- CONTENT_HTML ---
<h2 data-narration-id="n1">How Computers Store Images</h2>
<p data-narration-id="n2">Every digital image is built from a grid of tiny coloured squares called <dfn class="term" data-def="The smallest individual element of a digital image. Short for picture element.">pixels</dfn>. Each pixel stores a single colour value represented in binary. The more pixels an image contains, the more detail it can show &mdash; but the larger the file it produces.</p>
<p data-narration-id="n3">The total number of pixels in an image is given by its <dfn class="term" data-def="The dimensions of a bitmap image measured in pixels: width &times; height.">image size</dfn>. A 640 &times; 480 image contains 307,200 pixels. A 1920 &times; 1080 (Full HD) image contains 2,073,600 pixels. Zooming in on a low-resolution image reveals visible pixel squares &mdash; this is because there are fewer pixels packed into the same display area.</p>

<div class="key-fact" data-narration-id="n4" data-revision-tip="Cover this and write the formula for image file size in bits, then convert your answer to bytes. Then check.">
  <div class="key-fact-label">Key Fact</div>
  <p>Image file size (bits) = W &times; H &times; D, where W is width in pixels, H is height in pixels, and D is <strong>colour depth</strong> in bits. To convert to bytes, divide by 8.</p>
</div>

<h2 data-narration-id="n5">Colour Depth</h2>
<p data-narration-id="n6"><dfn class="term" data-def="The number of bits used to represent the colour of each pixel. More bits means a greater range of possible colours.">Colour depth</dfn> determines how many different colours are available for each pixel. With 1-bit colour depth, only 2 colours are possible (black and white). With 8-bit depth, 256 colours are possible. With 24-bit depth &mdash; often called &ldquo;true colour&rdquo; &mdash; over 16 million distinct colours can be represented, which appears photorealistic to the human eye.</p>
<p data-narration-id="n7">Increasing the colour depth improves visual quality but increases file size. A 100 &times; 100 image at 8-bit colour depth requires 80,000 bits (10,000 bytes). The same image at 24-bit colour depth requires 240,000 bits (30,000 bytes) &mdash; three times as large.</p>

    <p data-narration-id="n9"><strong>Step 1</strong> &mdash; Apply the formula: Size (bits) = W &times; H &times; D = 800 &times; 600 &times; 24 = 11,520,000 bits.</p>

    <p data-narration-id="n12"><strong>Common mistake:</strong> Forgetting to divide by 8. The formula gives bits &mdash; always convert to bytes for the final answer unless the question specifies bits.</p>

<h2 data-narration-id="n13">Converting Between Bitmaps and Binary</h2>
<p data-narration-id="n14">A simple 1-bit bitmap uses just 0s and 1s &mdash; 0 for white and 1 for black (or vice versa). Given a grid of binary values you can reconstruct the image pixel by pixel. For example, a 4 &times; 4 grid with binary row <code>1100</code> produces two black pixels followed by two white pixels on that row. In exam questions you may be asked to draw a small pixel image from a binary pattern, or to write out the binary for a given black-and-white image.</p>

<div class="key-fact" data-narration-id="n15" data-revision-tip="Test yourself: a 4-bit colour depth gives how many possible colours? Write your calculation.">
  <div class="key-fact-label">Key Fact</div>
  <p>The number of colours available at a given colour depth = 2<sup>depth</sup>. So 4-bit = 2<sup>4</sup> = 16 colours; 8-bit = 2<sup>8</sup> = 256 colours; 24-bit = 2<sup>24</sup> = 16,777,216 colours. Doubling the bit depth squares the number of available colours.</p>
</div>

<h2 data-narration-id="n16">How Sound Is Stored</h2>
<p data-narration-id="n17">Sound is an <dfn class="term" data-def="A signal that varies continuously over time, such as the pressure waves that make up sound.">analogue signal</dfn> &mdash; a continuous wave of varying air pressure. Computers cannot store continuous signals directly, so sound must be converted to digital form by taking regular measurements called <dfn class="term" data-def="A measurement of the amplitude of a sound wave taken at a single point in time, recorded as a binary number.">samples</dfn>. Each sample captures the amplitude (volume level) of the sound at that moment.</p>
<p data-narration-id="n18">This conversion from analogue to digital is performed by an analogue-to-digital converter (ADC). Playback reverses the process through a digital-to-analogue converter (DAC), turning the stored numbers back into a continuous wave through a speaker.</p>

<h2 data-narration-id="n19">Sampling Rate and Sample Resolution</h2>
<p data-narration-id="n20"><dfn class="term" data-def="The number of samples taken per second when digitising sound, measured in hertz (Hz).">Sampling rate</dfn> is how many samples are captured every second, measured in hertz (Hz). A higher sampling rate captures the original sound wave more faithfully because it takes more measurements. CD-quality audio uses a sampling rate of 44,100 Hz &mdash; meaning 44,100 measurements are made every second.</p>
<p data-narration-id="n21"><dfn class="term" data-def="The number of bits used to store each individual sound sample, also called bit depth. More bits means more precise volume levels can be recorded.">Sample resolution</dfn> (also called bit depth) is the number of bits used for each sample. A higher sample resolution captures more precise volume levels. CD-quality audio uses a 16-bit sample resolution, giving 65,536 possible amplitude levels per sample. Higher sample resolution produces richer, more detailed sound.</p>

<div class="key-fact" data-narration-id="n22" data-revision-tip="Cover this. Write out the sound file size formula from memory, then use it: rate 44,100 Hz, resolution 16 bits, duration 10 seconds.">
  <div class="key-fact-label">Key Fact</div>
  <p>Sound file size (bits) = sampling rate &times; sample resolution &times; duration (seconds). To convert to bytes, divide by 8. Always check which unit the question asks for.</p>
</div>

    <p data-narration-id="n23"><strong>Problem:</strong> A 60-second piece of music is recorded at CD quality: sampling rate 44,100 Hz, sample resolution 16 bits. Calculate the file size in megabytes.</p>
    <p data-narration-id="n24"><strong>Step 1</strong> &mdash; Apply the formula: Size (bits) = 44,100 &times; 16 &times; 60 = 42,336,000 bits.</p>
    <p data-narration-id="n25"><strong>Step 2</strong> &mdash; Convert to bytes: 42,336,000 &divide; 8 = 5,292,000 bytes.</p>
    <p data-narration-id="n26"><strong>Step 3</strong> &mdash; Convert to megabytes (1 MB = 1,000,000 bytes): 5,292,000 &divide; 1,000,000 = 5.292 MB &asymp; 5.3 MB.</p>
    <p data-narration-id="n27"><strong>Note:</strong> This is for a single audio channel (mono). Stereo audio would double the file size to roughly 10.6 MB for 60 seconds. This is why CD-quality audio needs compression (MP3) to be practical for streaming.</p>
  </div></div>
</div>

<h2 data-narration-id="n28">Quality Versus File Size</h2>
<p data-narration-id="n29">Both image and sound files face the same trade-off: higher quality always means larger file size. For images, increasing resolution (more pixels) or colour depth (more bits per pixel) improves quality but uses more storage. For sound, increasing sampling rate or sample resolution captures the audio more accurately but grows the file. In practice, file size is managed through compression &mdash; covered in the next lesson.</p>
<p data-narration-id="n30"><dfn class="term" data-def="Additional information stored alongside media data, such as the width, height and colour depth of an image or the sampling rate and resolution of an audio file.">Metadata</dfn> is stored alongside the pixel or sample data. For a bitmap image, metadata includes the width, height and colour depth. For a sound file, it includes the sampling rate and sample resolution. Metadata is not counted in the main file size calculation but it is always present in real files.</p>

--- CONCLUSION_HTML ---
<h3 data-narration-id="n32">Key Takeaways</h3>
<ul>
  <li data-narration-id="n33">Bitmap images are stored as a grid of pixels. File size (bits) = W &times; H &times; D. Divide by 8 for bytes. Higher resolution or colour depth improves quality but increases file size.</li>
  <li data-narration-id="n34">Sound is sampled from an analogue wave. File size (bits) = sampling rate &times; sample resolution &times; duration. Higher sampling rate and sample resolution give better audio fidelity but larger files.</li>
  <li data-narration-id="n35">Both image and sound storage involve a quality/file-size trade-off. Metadata (width, height, colour depth, sampling rate) is stored alongside the main data but is not part of the core file size calculation.</li>
</ul>

--- EXAM_TIP_HTML ---
<p data-narration-id="n31">File size calculations are a staple exam question. Always show every step: write the formula, substitute the values, calculate the answer in bits, then divide by 8 for bytes and by 1,000 (or 1,000,000) for kilobytes or megabytes. The most common error is forgetting to divide by 8 when the question asks for bytes. Note that this specification uses the SI decimal prefixes: 1 kB = 1,000 bytes and 1 MB = 1,000,000 bytes &mdash; not 1,024. When answering questions about how quality affects file size, say &ldquo;increases file size because each pixel/sample requires more bits&rdquo; rather than just &ldquo;makes the file bigger&rdquo;.</p>
